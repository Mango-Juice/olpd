# 공간 실행기 v4 — 구현과 확인 범위

메모의 실행·반복·우선순위는 [공통 메모 수칙](game-rules.md)을 기준으로 한다. 조건이 맞는 첫 수칙을 매 행동마다 다시 선택하며, 실행 완료로 메모를 소모하지 않는다.

현재 등록 콘텐츠는 `spatial-v1`이다. 프롤로그·1장의 기존 입력·판정·메모장·애니메이션은 유지하고, 2~10장의 54개 장면을 공용 공간 실행기와 선언형 배치로 연결했다. 기획 문서의 미터·화면 좌표는 배치 가설이며 실제 충돌 기준은 코드의 월드 좌표다.

## 책임과 경계

- `src/campaign/spatial/engine.ts`: 보행·점프·접촉·지지면·운반·장력·장치 주기·광원 위치·목표 판정. 모든 장이 같은 크기와 점프 범위를 사용한다. 이동은 샘플링한 경로로 판정하고, 고체·물·틈·열기·끼임·바람을 구분한다.
- `src/campaign/spatial/{early,middle,late}.ts`: 각 장의 오브젝트, 실제 표면과 충돌체, 연결 규칙, 이동 경로와 완료 상태. 정답 문장이나 장면 ID에 따른 실행 분기는 두지 않는다.
- `src/campaign/run.ts`: 기존 메모 누적·작성권·삭제 비용·우선순위·죽음·입구 부활·재생 완료 경계. 이동 중 목표에 닿아도 실행 커서를 정상 종료한다. 주기 장치 대기는 실제 주기 단계와 현재 지침 커서를 함께 비교한다.
- `src/render/campaign-scene.ts`: 장면 렌더링을 조율한다. `campaign-art.ts`는 그리기, `campaign-entity-semantics.ts`는 엔티티 분류, `campaign-dimensions.ts`는 공용 치수를 맡는다. `spatial-geometry.ts`, `spatial-scene.ts`, 기존 `animation.ts`는 판정에 사용한 표면·충돌체와 기록 경로 및 상태 전이를 표현한다. 프레임 속도로 물리 결과를 바꾸지 않는다.
- `server/campaign-deepseek.ts`: 기존 한 번의 의도 해석을 유지한다. 걷는 매 단계, 충돌, 재생, 기존 메모 재적용에는 AI를 호출하지 않는다.

옛 장면별 실행기와 기존 intent fixture는 `tests/fixtures/quiet-worlds/` 및 `tests/fixtures/` 아래 역사적 회귀 자료로 보존한다. 실제 게임의 registry는 이를 참조하지 않는다. 런타임 공개 명사 표는 `src/campaign/public-kinds.ts`에 있고, 54개 spatial intent recipe는 테스트 fixture에만 있으며 현재 런타임은 장면별 실행 데이터로만 동작한다.

## 공간과 실패

공통 보행은 실제 지지면을 따라 진행한다. 고체에 닿으면 접촉 위치에서 막히고, 바닥이 끊기면 실제 가장자리에서 추락한다. 명시한 경로는 보존된 경유점 커서로 진행하며, 전진 지시도 안전한 분기를 자동 선택하지 않는다. 실행할 지시가 없으면 그 자리에서 멈추며 시스템이 이동을 보충하지 않는다. 상자의 옆 홈과 갈라진 다리는 같은 깊이 좌표를 판정과 화면에서 사용한다.

장치의 움직임은 논리 tick과 저작한 연결·주기로 계산한다. 상자·널빤지의 지지, 발판 탑승, 열린 문과 열쇠, 손잡이 장력과 추의 연결, 주기적 위험이 같은 실행기 안에서 바뀐다. 이미 닫힌 고체와 닫히는 동안 몸을 누르는 장치는 서로 다른 접촉 결과를 낸다. 안개 관찰이 다리를 새로 만들거나 특정 관찰 동사가 성공 자격이 되지는 않는다.

4-5→4-6은 실제 풍로 상태를, 6-2→6-3은 등불의 위치·부모 관계를 넘긴다. QA에서 장면을 단독 열 때의 초기 상태와 실제 이전 장면에서 넘기는 상태는 구분한다.

높은 걸쇠는 실제 접근 뒤에도 높이가 맞지 않으면 손이 닿지 않는다. 공동 운반 물체는 혼자 들거나 밀어 우회할 수 없다. 고정 손잡이·문을 잡은 주체는 접촉 범위 안에서만 이동하며, 점프·사다리·탑승도 이 경계를 따른다. 움직이는 발판 때문에 범위를 벗어나면 손을 놓고 장치 상태를 갱신한다.

## 저장

실행 형식은 `StageRun v3`, 콘텐츠 판본은 `spatial-v1`, 캠페인 저장 문서는 v4다. v2·v3 문서의 이전 월드 실행은 그대로 복구 영역에 보관한다. 기존 완료 시각·해금과 1장 저장을 유지하며, 옛 완료를 새 지형에서 검증한 기록으로 바꾸지 않는다. QA는 `one-line-per-death:qa:spatial-v1` 슬롯을 쓰고 이전 슬롯은 삭제하지 않는다.

기록된 이동 경로는 유한 좌표·순서가 있는 시간 값·점 개수를 검증한다. 저장을 불러와 재생할 때 물리나 AI를 다시 호출하지 않는다.

## 검증 의미

`tests/spatial-campaign.test.ts`는 54개 장면의 명시적 해석 fixture로 실제 실행기와 직렬화를 확인하고, 9개 장에서 실패 뒤 한 줄을 추가하며 입구부터 다시 진행하는 흐름을 검사한다. 장별 테스트는 직진·반복 점프의 우회, 물체 인계, 협력과 접촉 원인을 따로 검사한다. 모델 응답을 합성한 검사는 실제 자연어 해석 정확도나 사람의 난이도 평가를 대신하지 않는다.

최종 실행 결과와 브라우저 확인 범위는 [검증 기록](verification.md)을 따른다. 새 비트맵 애니메이션 시트를 제작한 것은 아니며, 기존 캐릭터 원화와 공용 자세·물체별 그리기 및 상태 전이 연출을 조합한다.

## 발견 힌트

서사 프롤로그는 물리 발견 힌트와 별개이며 건너뛸 수 있다. 새 1장은 여섯 장면(1-1~1-6)이고 기존 진행 저장은 이전 네 단계 도입과 여덟 방을 유지한다. 1장과 2~10장의 발견 힌트 선택은 공용 `src/game/hints/discovery.ts`를 사용한다. 2~10장의 접촉·낙하·typed 상호작용 실패 문구는 `src/campaign/contact-hints.ts`와 `src/campaign/hints/`에 있다. 현재 장의 모든 여섯 장면 이벤트 이력을 검색해 아직 배우지 않은 가장 최근 발견 하나를 선택한다. 실제 접촉과 접근 실패, 장면 낙하 관측을 구분하며, 낙하를 오브젝트 접촉으로 꾸며내지 않는다. 장면별 검토는 [초반 힌트](stage-design/hint-review-early.md), [후반 힌트](stage-design/hint-review-late.md), [이전 1장 힌트 기록](stage-design/hint-review-first.md)을 참고한다.
