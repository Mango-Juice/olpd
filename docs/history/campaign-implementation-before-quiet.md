# 10장 캠페인 구현과 검증

2026-09-22 로컬 구현 기록. 배포된 사이트의 상태와 구분한다. 설계 원본은 [공통 규칙](../stage-design/00-play-contract.md)과 [장별 문서](../stage-design/README.md)다. 기존 프로토타입과 설계는 로컬 커밋 `7429b34`에 보존했다.

1장 도입은 `src/game/onboarding.ts`, 나머지 도입은 `src/campaign/stages/onboarding.ts`에 있다. 본편은 `src/campaign/stages/`의 장별 파일과 기존 1장 엔진을 사용한다. `registry.ts`가 도입과 본편을 합쳐 연결한다.

- 서사 프롤로그 SKIP은 이야기만 건너뛴다. 신규 플레이의 필수 도입을 생략하지 않는다.
- 실제 대상이 적은 별도 도입 장면을 배치했다. 같은 복잡한 장면의 설명만 접는 방식이 아니다.
- 공용 헤더·메모장·입력·미리보기·실마리·진행 표시를 사용하며, 내부 ID 대신 연속된 화면 번호를 표시한다.
- 1장 완료 후 여정 지도를 제공한다. 정상 캠페인에서는 바로 앞 장의 실제 완료가 다음 장을 연다.
- `http://localhost:5173/?qa=1`은 개발 서버의 loopback 전용 QA다. 장과 개별 스테이지를 바로 고르고, 일반 캠페인과 별도 저장한다. 운영 빌드에는 QA 진입 코드가 포함되지 않는다.
- 장별 배경·장치 상태·10개 합성 BGM 테마를 사용한다. 도입/main/climax 레이어는 물리 판정과 독립적이다. 문서의 악기 제안이 실제 악기 녹음을 뜻하지는 않는다.

## 도입, 본편과 저장 경계

도입의 임시 한 줄은 무료 수정·삭제·재실행이 가능하다. 종·사망·지우개를 소비하지 않는다. 완료 단계와 시도한 원문은 학습 기록으로 남으며 활성 본편 메모로 자동 복사하지 않는다. 6-1→6-2, 9-1→9-2만 명시된 성공 상태를 이어받는다.

마지막 도입 뒤 본편의 원래 첫 배치, 새 메모장, 본편 복귀점을 만든다. 1장은 빈 메모·무료 첫 작성·지우개 2개로 1-5에 들어간다. 2~9장은 본편 발견 기회 최대 5회, 10장은 6회다. 도입의 방문·재시작으로 이를 늘리지 않는다. 10장 봉인 복귀점은 화면 10-3/10-5/10-7이다.

기존 v2 본편 저장은 도입 면제로 읽고 기존 물건·메모·관측·완료 기록을 보존한다. 가짜 도입 완료 이력을 만들지 않는다. 1장 도입 기록도 일반 캠페인에서는 legacy 실행과 같은 IndexedDB 원자 저장에 포함해 다중 창 충돌 검사를 거친다. QA와 독립 실행용 저장 어댑터는 분리한다.

지난 장의 메모를 가져올 때에는 현재 장면에서 원문의 뜻을 다시 확인한 뒤 무료 복사한다. 과거 장의 물체 ID를 그대로 실행하지 않는다. 이때에도 명시적으로 요청한 문장 해석 1회만 호출하며, 첫 본편 출발 후에는 복사할 수 없다.

## 실행과 공정성

물리·완료 판정은 코드가 처리한다. AI에 정답이나 클리어 여부를 묻지 않는다. 순서·병렬·기다림·유지·해제를 실행 커서와 함께 저장하며, 배속과 현실 시간이 판정을 바꾸지 않는다.

관계로 지정한 대상은 `references`에 관측 출처를 보관하고 실제 행동 시작 때 현재 시도의 사실로 결정한다. 이전 시도 사실을 현재 답으로 쓰거나, 참조가 없을 때 숨은 실시간 연결로 대체하지 않는다. 이동 중에는 선택한 대상을 고정한다. 고정 손잡이의 일회 작동과 지속 유지도 구분한다.

기본 전진은 장면이 명시한, 공개되고 안전하며 유일한 보행 경로에서만 허용한다. 가드·실행 중 지침·명시적 대기가 우선한다. 탑승·하차·갈림길 선택·두 주체의 역할을 자동으로 해결하지 않는다. 도입에는 기본 전진을 적용하지 않는다. 예상 밖 위험을 만난 자동 전진은 원래 자리에서 무료로 멈춘다.

9장은 앞 구역의 물건과 장치 상태를 보존해 재사용한다. 10장은 세 봉인과 여섯 비트, 판자·쐐기 회수, 관측한 손잡이의 동일성, 실제 잠금판 접촉을 검사한다. 마지막 문은 두 주체가 안전선 안에 있고 용사가 편지를 지녔을 때 완료되며, 그 뒤에만 건너뛸 수 있는 편지 엔딩을 보여 준다.

## AI 호출과 비용

- 1장: 기존 Jev 1회. 후속 장: `deepseek-flash` 1회, 기본 non-thinking, 8초 제한.
- 자동 재호출·reasoning 승격·다른 provider fallback은 없다. 네트워크·명료화 오류는 게임 실패가 아니다.
- 입력은 현재 공개 세계와 현재 시도의 최신 관측, 사용자의 원문이다. 과거 전체 관측 로그·다른 메모 전체·숨은 현재 상태를 보내지 않는다.
- 속성 이름과 boolean 의미는 한 번의 공통 사전으로 보낸다. 중복 설명·빈 필드·중복 관측을 제거한다. 공개 장치의 가능한 상태 이름은 필요한 경우에만 `propertyOptions`로 제공한다.
- 출력은 실행 AST 또는 짧은 명료화 사유다. 장문의 해설·연출·성공 판정은 생성하지 않는다.
- 기존 27개 장면의 사용자 맥락 JSON 평균은 4,377.7B에서 3,771.8B로 13.84% 줄었다. 이는 **맥락 바이트 측정**이며, 새 참조 기능 때문에 커진 시스템 프롬프트까지 포함한 총 토큰 절감률은 아니다.

이전 Jev 캠페인 중단 근거와 DeepSeek 도입 과정은 [Jev 기록](../campaign-jev-probe.md), [DeepSeek 실측](../campaign-deepseek-probe.md)에 남아 있다. 과거 중단 상태가 현재 구현 상태를 대신하지 않는다.

## 검증 경계와 실행 방법

```sh
pnpm test
pnpm build
pnpm exec tsx scripts/browser-all-stages.ts
pnpm exec tsx scripts/browser-onboarding-flow.ts
pnpm exec tsx scripts/browser-legacy-onboarding.ts
# 실제 비용이 발생하는 별도 검사
pnpm exec tsx scripts/evaluate-legacy-onboarding-live.ts
pnpm exec tsx --env-file=.env.local scripts/evaluate-onboarding-live.ts
pnpm eval:campaign --repeat=1
```

`campaign-content-contract.test.ts`는 총 80개, 각 장의 개수·ID·초기 상태·공개 속성·새 저장을 검사한다. 장별 테스트는 A/B 물리 경로와 실패·되감기·관측·저장 복원을 검증한다. typed fixture의 성공을 자유 자연어 성공으로 세지 않는다.

브라우저 검사에서 후속 장 68개 화면의 실제 렌더링과 QA 이동, 모바일 가로 넘침, 도입 인계·수정·재접속을 확인한다. provider 경계 stub을 쓰는 UI 검사는 API 정확도 측정과 분리한다. 실호출 기록은 `artifacts/`에 요청·최종 응답·사용량·지연·프롬프트 버전과 함께 보관하며 키와 authorization 헤더는 기록하지 않는다.

자동화 성공은 모든 자유 문장의 해석 정확도나 사람에게 느껴지는 재미를 보장하지 않는다. 초회 플레이 시간과 난도·힌트 밀도·음악의 피로도는 사용자 플레이로 확인할 항목이다. 최종 실행 수치와 남은 한계는 아래 통합 검증 기록에 정리한다.


## 통합 검증 기록 — 2026-09-22

| 검사 | 관측 결과 |
| --- | --- |
| `pnpm test` | 49개 파일, 490개 테스트 통과 |
| `pnpm build` | 타입 검사·프로덕션 빌드 통과. 주 JS 청크 788.96kB(압축 전)로 500kB 경고는 남음 |
| 후속 장 QA 화면 | 68개 장면 렌더링·개별 이동, 모바일 가로 넘침 없음, 런타임 오류 없음 |
| 도입 브라우저 흐름 | 1장 4개 도입과 2장 3개 도입, 수정·재접속·빈 본편 수첩 인계 확인 |
| 실제 Jev | 1장 도입 대표 문장 4/4 통과 |
| 실제 DeepSeek v14 | 도입 22/22, 의미·물리 회귀 27/27, 8–10장 본편 대표 힌트 16/16 통과 |
| 실제 HTTP 연결 | 2장 첫 도입 1회 실제 API 사용 후 나머지 흐름은 stub으로 검증 |

DeepSeek 최종 세 묶음은 같은 v14 프롬프트로 각각 한 번씩 호출한 결과다. 앞선 실패를 삭제하거나 재시도를 통과율에 합치지 않았다. 최종 예시에서도 자유로운 다른 문장을 모두 이해한다고 보장하지 않는다. 특히 후반 검사는 물리 완료를 검사하며, 모든 생성 프로그램의 의도 보존을 자동 판정하지는 않는다. 관측 참조·A/B 경로·실패 처리는 별도 typed 테스트로 확인했다.

후반부 조율 중 발견한 문제는 9장 회수 경로 힌트의 등반 누락, 관찰한 연결 대상의 불명확한 지칭, 한 사람의 복수 관찰을 동시 행동으로 만드는 모델 출력이었다. 안내에 실제 필요한 동작·참조 주체·순서를 명시했다. 모호하거나 실행할 수 없는 출력은 무료 확인으로 돌아가며, 자동 재호출로 비용을 늘리지 않는다.

실측 지연·토큰·원본 경로는 [DeepSeek 검증 기록](../campaign-deepseek-probe.md#80개-스테이지-통합-검증--2026-09-22)에 정리했다. 배포·push는 하지 않았으며, localhost QA에서 모든 장과 개별 스테이지를 열 수 있다.
