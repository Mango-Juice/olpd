# 8장 — 안개 신호장

> 현재 설계 v2 · 6장면 · 기준 화면 960×500. 코드와 검증 상태는 별도로 확인한다. 이전 복합 설계는 [역사 기록](../history/stage-design-v1/README.md)이며 구현 요구사항이 아니다.

## 장의 중심 — 보고 나서 움직인다

모든 관찰 대상과 결과는 같은 화면 안에 있고 관측 장부를 요구하지 않는다.

[공통 플레이 계약](00-play-contract.md)을 따른다. 현재 장면에서 무료로 문장을 고치고 다시 해 본다. 이미 마친 장면을 다시 통과할 필요는 없다. 이전 장의 설명서나 물체 속성표를 읽어야 풀리는 장면은 만들지 않는다.

## 사용자에게 보이는 문구

입장할 때 아래 목적 한 문장을 한 번 보여 주고 구분에 필요한 사물 이름만 남긴다. 확인 팝업은 없다. 명령 예시, 요소 역할, 세부 완료 판정과 해법은 개발자용 정보이며 UI에 표시하지 않는다. 해야 할 일은 알리되 해결 순서는 말하지 않는다.

| 장면 | 입장 목적 한 문장 |
| --- | --- |
| 8-1 안개 속 다리 | 안개 너머 출구로 건너가야 해요. |
| 8-2 끊긴 쪽 보기 | 건너편 섬에 닿아야 해요. |
| 8-3 바람 깃발 | 바람길 너머로 가야 해요. |
| 8-4 등불의 윤곽 | 안개 속 위층에 올라가야 해요. |
| 8-5 문양이 닿는 곳 | 다리 너머 출구에 닿아야 해요. |
| 8-6 출발 신호 | 건너편 부두로 가야 해요. |

## 제작·검증용 장면 명세

아래 수와 역할은 내부 설계 검증용이다. 도착점·위험·관찰 대상·조작 물건을 모두 세며, 일반 바닥과 배경 장식만 제외한다. 연결된 물건을 묶어 수를 숨기지 않는다. 용사와 등지기는 수에서 제외하지만 등지기의 별도 역할은 인지 부담으로 검토한다.

### 8-1. 안개 속 다리

- **요소 3개:** 옅은 안개 — 관찰 대상, 돌다리 — 길, 출구 — 목표.
- **공간:** 안개가 중앙 다리의 윤곽만 가리고 양끝은 같은 화면에 보인다. 카메라 이동이나 가로 스크롤 없이 출발과 결과가 함께 보인다.
- **단일 목표:** 다리를 확인하고 건넌다.
- **최소 의도 예시 — 사용자 비노출:** “안개 속 길을 살펴보고 돌다리로 건너.” 같은 의도를 다른 문장으로 써도 인정한다.
- **이번 장면의 한 초점:** 관찰로 드러나는 길. 익힌 동작은 새 설명 없이 재사용한다.
- **눈으로 보이는 인과:** 같은 화면 안의 다리 윤곽이 선명해진다.
- **회복:** 실패한 접촉이나 멈춘 이유를 짧게 보여 주고 현재 장면의 시작 배치에서 무료로 다시 한다. 해석이 불명확하면 실행 전에 무료로 확인한다.

### 8-2. 끊긴 쪽 보기

- **요소 3개:** 왼쪽 다리 — 끊긴 길, 오른쪽 다리 — 온전한 길, 도착 섬 — 목표.
- **공간:** 아래 분기에서 두 다리가 위쪽 섬으로 향한다. 카메라 이동이나 가로 스크롤 없이 출발과 결과가 함께 보인다.
- **단일 목표:** 온전한 다리로 섬에 닿는다.
- **최소 의도 예시 — 사용자 비노출:** “다리를 살펴보고 이어진 쪽으로 가.” 같은 의도를 다른 문장으로 써도 인정한다.
- **이번 장면의 한 초점:** 관찰로 대상 고르기. 익힌 동작은 새 설명 없이 재사용한다.
- **눈으로 보이는 인과:** 끊긴 끝과 이어진 끝이 서로 다른 실루엣으로 드러난다.
- **회복:** 실패한 접촉이나 멈춘 이유를 짧게 보여 주고 현재 장면의 시작 배치에서 무료로 다시 한다. 해석이 불명확하면 실행 전에 무료로 확인한다.

### 8-3. 바람 깃발

- **요소 3개:** 깃발 — 관찰 단서, 바람길 — 위험, 출구 — 목표.
- **공간:** 중앙 바람길 바로 위에 깃발이 매달려 있다. 카메라 이동이나 가로 스크롤 없이 출발과 결과가 함께 보인다.
- **단일 목표:** 바람이 멎었을 때 길을 지난다.
- **최소 의도 예시 — 사용자 비노출:** “깃발이 가라앉으면 지나가.” 같은 의도를 다른 문장으로 써도 인정한다.
- **이번 장면의 한 초점:** 단서와 현상의 연결. 익힌 동작은 새 설명 없이 재사용한다.
- **눈으로 보이는 인과:** 깃발과 바람 입자가 함께 가라앉는다.
- **회복:** 실패한 접촉이나 멈춘 이유를 짧게 보여 주고 현재 장면의 시작 배치에서 무료로 다시 한다. 해석이 불명확하면 실행 전에 무료로 확인한다.

### 8-4. 등불의 윤곽

- **요소 3개:** 등불 — 도구, 안개 낀 계단 — 관찰과 길, 위층 — 목표.
- **공간:** 계단이 중앙에서 위층까지 오르며 등불은 앞쪽에 있다. 카메라 이동이나 가로 스크롤 없이 출발과 결과가 함께 보인다.
- **단일 목표:** 계단을 확인하며 위층에 오른다.
- **최소 의도 예시 — 사용자 비노출:** “등불로 계단을 비추고 올라가.” 같은 의도를 다른 문장으로 써도 인정한다.
- **이번 장면의 한 초점:** 도구로 보기. 익힌 동작은 새 설명 없이 재사용한다.
- **눈으로 보이는 인과:** 빛을 받은 계단 윤곽이 차례로 드러난다.
- **회복:** 실패한 접촉이나 멈춘 이유를 짧게 보여 주고 현재 장면의 시작 배치에서 무료로 다시 한다. 해석이 불명확하면 실행 전에 무료로 확인한다.

### 8-5. 문양이 닿는 곳

- **요소 4개:** 관측창 — 관찰, 삼각 다리 — 온전한 길, 원형 다리 — 끊긴 길, 출구 — 목표.
- **공간:** 중앙 창 너머에서 길이 위아래로 갈라지고 한 출구에서 만난다. 카메라 이동이나 가로 스크롤 없이 출발과 결과가 함께 보인다.
- **단일 목표:** 이어진 다리로 출구에 닿는다.
- **최소 의도 예시 — 사용자 비노출:** “창으로 보고 이어진 다리로 가.” 같은 의도를 다른 문장으로 써도 인정한다.
- **이번 장면의 한 초점:** 확인한 모양의 사용. 익힌 동작은 새 설명 없이 재사용한다.
- **눈으로 보이는 인과:** 창을 볼 때 삼각 다리의 연결이 같은 화면에서 선명해진다.
- **회복:** 실패한 접촉이나 멈춘 이유를 짧게 보여 주고 현재 장면의 시작 배치에서 무료로 다시 한다. 해석이 불명확하면 실행 전에 무료로 확인한다.

### 8-6. 출발 신호

- **요소 4개:** 신호 깃발 — 관찰, 나룻배 — 운반, 물길 — 위험, 도착 부두 — 목표.
- **공간:** 배가 왼쪽 아래와 오른쪽 위 부두 사이를 오간다. 카메라 이동이나 가로 스크롤 없이 출발과 결과가 함께 보인다.
- **단일 목표:** 정박한 배로 건넌다.
- **최소 의도 예시 — 사용자 비노출:** “깃발이 내려가면 배를 타.” 같은 의도를 다른 문장으로 써도 인정한다.
- **이번 장면의 한 초점:** 관찰과 사건의 재회. 익힌 동작은 새 설명 없이 재사용한다.
- **눈으로 보이는 인과:** 정박과 깃발 내림이 함께 보이고 이후 용사가 탄다.
- **회복:** 실패한 접촉이나 멈춘 이유를 짧게 보여 주고 현재 장면의 시작 배치에서 무료로 다시 한다. 해석이 불명확하면 실행 전에 무료로 확인한다.

관찰은 같은 화면의 안개 농도·가려진 연결 윤곽을 바꾼다. 새 창, 확대 화면, 물리 속성 패널, 사실 목록은 열지 않는다. 관찰 사실을 별도 장부에 옮겨 적거나 시도마다 다시 인증할 필요가 없다. 알아낸 대상을 직접 지목해도 동일한 실제 결과를 인정한다.

## 이야기와 장의 음악

오래된 화물표. “먼저 보고 말해 주던 네가 있었지.”

이야기 소품은 장면 완료 뒤 짧은 선택 장면으로 보여 준다. 퍼즐 화면의 상호작용 대상이나 숨은 조건으로 추가하지 않는다. 모루와 편지, 등지기의 기존 서사 연결과 용사의 외형은 유지한다.

- **대표 분위기:** 안개 너머에서 천천히 윤곽을 알아보는 고요한 호기심. 모르는 것은 공포나 불길함이 아니라 더 살펴볼 빈 공간이다.
- **음색:** 숨을 섞은 플루트, 약음기를 댄 현, 멀리 번지는 낮은 건반. 실제 높은 종·낮은 종 신호와 혼동할 음악 속 종 패턴은 쓰지 않는다.

여섯 장면은 같은 장의 모티프를 이어 쓴다. 첫 장면은 성기게, 마지막에는 음색을 조금 모으되 실제 장치 소리와 구분한다. 실패 때 곡을 처음부터 재생하거나 음악으로 정답을 알려 주지 않는다. 음소거에서도 움직임과 인과를 모두 읽을 수 있다. 음악 제작 제안이며 새 음원 구현을 뜻하지 않는다.

## 이 장의 검증 경계

- 960×500 안에서 필수 요소와 출발·결과가 동시에 보이며 화면 밖 대상이나 가로 스크롤이 없다.
- 목적 한 문장 이외의 설명 없이도 무엇이 막혔고 행동 뒤 무엇이 바뀌었는지 몸·공간·움직임으로 읽힌다.
- 최초 장면은 한두 의도로 끝나고, 후반 재회도 긴 문장이나 물리 계산을 요구하지 않는다.
- 장면별 이름·요소 수·인과가 실제 렌더링과 일치한다. 장식으로 보이는 숨은 정답 물체가 없다.
- 실패 뒤 현재 장면만 다시 하며 문장 수정 비용과 앞 장면 재플레이가 없다.
- 플레이 시간과 재미는 사람 플레이로 검증하기 전까지 수치 성과로 주장하지 않는다.
