# 2장 — 비에 잠긴 회랑

> 현재 설계 v2 · 6장면 · 기준 화면 960×500. 코드와 검증 상태는 별도로 확인한다. 이전 복합 설계는 [역사 기록](../history/stage-design-v1/README.md)이며 구현 요구사항이 아니다.

## 장의 중심 — 물건이 길을 바꾼다

상자·물·나무의 접촉을 한 번에 하나씩 경험한다.

[공통 플레이 계약](00-play-contract.md)을 따른다. 현재 장면에서 무료로 문장을 고치고 다시 해 본다. 이미 마친 장면을 다시 통과할 필요는 없다. 이전 장의 설명서나 물체 속성표를 읽어야 풀리는 장면은 만들지 않는다.

## 사용자에게 보이는 문구

입장할 때 아래 목적 한 문장을 한 번 보여 주고 구분에 필요한 사물 이름만 남긴다. 확인 팝업은 없다. 명령 예시, 요소 역할, 세부 완료 판정과 해법은 개발자용 정보이며 UI에 표시하지 않는다. 해야 할 일은 알리되 해결 순서는 말하지 않는다.

| 장면 | 입장 목적 한 문장 |
| --- | --- |
| 2-1 막힌 빗길 | 편지와 함께 회랑을 건너야 해요. |
| 2-2 높은 창 | 높은 창가에 올라가야 해요. |
| 2-3 끊긴 바닥 | 편지와 함께 건너편으로 가야 해요. |
| 2-4 떠 있는 발판 | 편지와 함께 물 건너로 가야 해요. |
| 2-5 잠긴 아래 계단 | 아래 계단으로 내려가야 해요. |
| 2-6 처진 다리 | 편지와 함께 회랑을 나가야 해요. |

## 제작·검증용 장면 명세

아래 수와 역할은 내부 설계 검증용이다. 도착점·위험·관찰 대상·조작 물건을 모두 세며, 일반 바닥과 배경 장식만 제외한다. 연결된 물건을 묶어 수를 숨기지 않는다. 용사와 등지기는 수에서 제외하지만 등지기의 별도 역할은 인지 부담으로 검토한다.

### 2-1. 막힌 빗길

- **요소 2개:** 짐상자 — 이동 장애, 출구 — 목표.
- **공간:** 중앙의 상자가 오른쪽 통로를 막는다. 카메라 이동이나 가로 스크롤 없이 출발과 결과가 함께 보인다.
- **단일 목표:** 출구에 도착한다.
- **최소 의도 예시 — 사용자 비노출:** “상자를 옆으로 밀고 출구로 가.” 같은 의도를 다른 문장으로 써도 인정한다.
- **이번 장면의 한 초점:** 위치 변화. 익힌 동작은 새 설명 없이 재사용한다.
- **눈으로 보이는 인과:** 상자가 옆으로 움직이고 통로가 드러난다.
- **회복:** 실패한 접촉이나 멈춘 이유를 짧게 보여 주고 현재 장면의 시작 배치에서 무료로 다시 한다. 해석이 불명확하면 실행 전에 무료로 확인한다.

### 2-2. 높은 창

- **요소 2개:** 나무상자 — 발판, 창가 — 높은 목표.
- **공간:** 상자는 왼쪽 아래, 창가는 오른쪽 위에 가깝게 놓인다. 카메라 이동이나 가로 스크롤 없이 출발과 결과가 함께 보인다.
- **단일 목표:** 창가에 올라선다.
- **최소 의도 예시 — 사용자 비노출:** “상자를 창가 밑에 놓고 올라가.” 같은 의도를 다른 문장으로 써도 인정한다.
- **이번 장면의 한 초점:** 올라설 받침. 익힌 동작은 새 설명 없이 재사용한다.
- **눈으로 보이는 인과:** 상자를 딛고 창가로 이어지는 두 짧은 움직임을 보인다.
- **회복:** 실패한 접촉이나 멈춘 이유를 짧게 보여 주고 현재 장면의 시작 배치에서 무료로 다시 한다. 해석이 불명확하면 실행 전에 무료로 확인한다.

### 2-3. 끊긴 바닥

- **요소 3개:** 널빤지 — 다리, 바닥 틈 — 위험, 건너편 — 목표.
- **공간:** 짧은 중앙 틈 옆에 틈보다 조금 긴 판자가 놓인다. 카메라 이동이나 가로 스크롤 없이 출발과 결과가 함께 보인다.
- **단일 목표:** 건너편에 도착한다.
- **최소 의도 예시 — 사용자 비노출:** “널빤지를 걸치고 건너.” 같은 의도를 다른 문장으로 써도 인정한다.
- **이번 장면의 한 초점:** 양쪽을 잇는 지지. 익힌 동작은 새 설명 없이 재사용한다.
- **눈으로 보이는 인과:** 판자의 양끝이 돌턱에 닿은 뒤 용사가 밟는다.
- **회복:** 실패한 접촉이나 멈춘 이유를 짧게 보여 주고 현재 장면의 시작 배치에서 무료로 다시 한다. 해석이 불명확하면 실행 전에 무료로 확인한다.

### 2-4. 떠 있는 발판

- **요소 3개:** 코르크 발판 — 부유 지지, 물웅덩이 — 위험, 건너편 — 목표.
- **공간:** 물 가운데 넓은 발판 하나가 양쪽 돌턱 가까이 떠 있다. 카메라 이동이나 가로 스크롤 없이 출발과 결과가 함께 보인다.
- **단일 목표:** 물을 밟지 않고 건넌다.
- **최소 의도 예시 — 사용자 비노출:** “발판을 밟고 건너.” 같은 의도를 다른 문장으로 써도 인정한다.
- **이번 장면의 한 초점:** 떠 있는 지지도 밟을 수 있음. 익힌 동작은 새 설명 없이 재사용한다.
- **눈으로 보이는 인과:** 발판이 살짝 잠겼다가 떠오르며 용사를 받친다.
- **회복:** 실패한 접촉이나 멈춘 이유를 짧게 보여 주고 현재 장면의 시작 배치에서 무료로 다시 한다. 해석이 불명확하면 실행 전에 무료로 확인한다.

### 2-5. 잠긴 아래 계단

- **요소 3개:** 배수 덮개 — 조작, 고인 물 — 위험, 아래 계단 — 목표.
- **공간:** 오른쪽 계단의 아래 부분만 물에 잠기고 덮개는 마른 바닥에 있다. 카메라 이동이나 가로 스크롤 없이 출발과 결과가 함께 보인다.
- **단일 목표:** 아래 계단에 도착한다.
- **최소 의도 예시 — 사용자 비노출:** “덮개를 열고 계단으로 내려가.” 같은 의도를 다른 문장으로 써도 인정한다.
- **이번 장면의 한 초점:** 환경 상태 변화. 익힌 동작은 새 설명 없이 재사용한다.
- **눈으로 보이는 인과:** 물이 빠지며 숨겨졌던 계단 윤곽이 드러난다.
- **회복:** 실패한 접촉이나 멈춘 이유를 짧게 보여 주고 현재 장면의 시작 배치에서 무료로 다시 한다. 해석이 불명확하면 실행 전에 무료로 확인한다.

### 2-6. 처진 다리

- **요소 3개:** 상자 — 받침, 처진 다리 — 길, 출구 — 목표.
- **공간:** 중앙 다리 아래에 상자를 밀어 넣을 빈자리가 보인다. 카메라 이동이나 가로 스크롤 없이 출발과 결과가 함께 보인다.
- **단일 목표:** 다리를 지나 출구에 도착한다.
- **최소 의도 예시 — 사용자 비노출:** “상자로 다리를 받치고 건너.” 같은 의도를 다른 문장으로 써도 인정한다.
- **이번 장면의 한 초점:** 지지의 응용. 익힌 동작은 새 설명 없이 재사용한다.
- **눈으로 보이는 인과:** 상자가 다리를 받치면 다리가 수평으로 멈춘다.
- **회복:** 실패한 접촉이나 멈춘 이유를 짧게 보여 주고 현재 장면의 시작 배치에서 무료로 다시 한다. 해석이 불명확하면 실행 전에 무료로 확인한다.

## 이야기와 장의 음악

회랑 끝의 낮은 우비 걸이 두 개. “왼쪽 고리는 늘 비워 뒀던 것 같은데.”

이야기 소품은 장면 완료 뒤 짧은 선택 장면으로 보여 준다. 퍼즐 화면의 상호작용 대상이나 숨은 조건으로 추가하지 않는다. 모루와 편지, 등지기의 기존 서사 연결과 용사의 외형은 유지한다.

- **대표 분위기:** 비 그친 돌길에서 물건을 만져 보는 호기심. 축축하고 차가운 공간 안에 코르크와 나무의 가벼운 온기가 섞인다.
- **음색:** 물방울을 연상시키는 성긴 셀레스타, 둥근 마림바, 가볍게 뜯는 현. 빗소리·물살은 별도 환경음이며 음악의 물방울 음이 실제 수위나 유량 신호처럼 들리지 않게 한다.

여섯 장면은 같은 장의 모티프를 이어 쓴다. 첫 장면은 성기게, 마지막에는 음색을 조금 모으되 실제 장치 소리와 구분한다. 실패 때 곡을 처음부터 재생하거나 음악으로 정답을 알려 주지 않는다. 음소거에서도 움직임과 인과를 모두 읽을 수 있다. 음악 제작 제안이며 새 음원 구현을 뜻하지 않는다.

## 이 장의 검증 경계

- 960×500 안에서 필수 요소와 출발·결과가 동시에 보이며 화면 밖 대상이나 가로 스크롤이 없다.
- 목적 한 문장 이외의 설명 없이도 무엇이 막혔고 행동 뒤 무엇이 바뀌었는지 몸·공간·움직임으로 읽힌다.
- 최초 장면은 한두 의도로 끝나고, 후반 재회도 긴 문장이나 물리 계산을 요구하지 않는다.
- 장면별 이름·요소 수·인과가 실제 렌더링과 일치한다. 장식으로 보이는 숨은 정답 물체가 없다.
- 실패 뒤 현재 장면만 다시 하며 문장 수정 비용과 앞 장면 재플레이가 없다.
- 플레이 시간과 재미는 사람 플레이로 검증하기 전까지 수치 성과로 주장하지 않는다.
