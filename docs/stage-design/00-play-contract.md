# 플레이 계약 v3 — 한 화면과 하나의 메모장

이 문서는 `shared-v1` 캠페인의 현재 기준이다. 1장의 메모 누적·우선순위·죽음 뒤 한 줄·지우개·입구 재시작 계약을 공용 코어 정책·UI·재생 모듈로 2~10장까지 이어 간다. 장 콘셉트·모루·편지·등지기·장별 음악과 현재 54개 장면의 공간·성공 판정은 유지한다. 장면마다 메모장을 비우고 무료 한 줄을 받던 `quiet-v1` 규칙은 폐기되었으며 현재 요구사항이 아니다.

## 공간이 먼저 설명한다

- 기준 화면은 **960×500 고정 구도**다. 화면 크기에 맞춘 전체 비율 축소는 허용하지만 확대 조작·카메라 이동·가로 스크롤로 대상 찾기를 요구하지 않는다.
- 한 장면은 하나의 공간 상황, 하나의 목표, 하나의 새 개념 또는 이미 배운 한 관계의 재회다. 복잡해지면 별도 장면으로 나눈다.
- 2~4장은 도착점·위험·조작물·관찰 대상을 모두 합해 **최대 4개**다. 5~10장도 4개를 기본 상한으로 삼고 현재 54개 장면은 모두 이를 지킨다. 다섯 번째 요소가 꼭 필요하면 먼저 장면 분할을 검토하고 독립 근거를 남긴다.
- 용사와 동료는 위 수에서 제외해도 각각의 역할이 인지 부담임을 고려한다. 둘이 함께 있어야 할 이유가 없는 장면에서는 동료에게 별도 판단을 맡기지 않는다.
- 조작 가능한 연결 부품을 배경이나 복합 장치 하나로 묶어 수를 숨기지 않는다. 일반 바닥은 배경이지만 위험한 틈과 전용 이동 발판은 센다.
- 요소는 높이·거리·길·가림·접촉을 가진 공간에 놓는다. 같은 크기의 물체 카드나 아이콘을 한 줄로 세운 퍼즐, 물체 목록 갤러리로 대체하지 않는다.

## 사용자 문구와 내부 명세를 나눈다

입장할 때 **해야 할 일만 한 문장으로 한 번** 말한다. 장면마다 목적이 다르면 그 목적을 바꿔 말한다. 예를 들어 편지와 함께 회랑을 건너기, 빵 꺼내기, 등지기와 합류하기를 짧게 알린다. 이를 닫기 위한 팝업이나 확인 버튼은 없다.

- 목표는 무엇을 이루는지만 말한다. 어떤 물건부터 만질지, 어떤 조건을 만족할지, 해결 순서는 알려 주지 않는다.
- 이름이 없으면 대상을 구분하기 어려운 사물에만 짧은 이름을 붙인다. 물체별 목표 설명·상세 속성·사용법은 표시하지 않는다.
- 무게·압력·범위·슬롯·내부 상태값·조건표·해결 체크리스트·상태 요약 패널·정답 예시를 사용자 화면에 내보내지 않는다.
- 모양, 위치, 움직임, 손의 접촉, 줄의 장력, 물의 흐름과 행동 뒤 변화를 통해 인과를 읽는다. 색만으로 구별하지 않는다.
- 장 문서의 요소 수, 역할, 완료 판정, 최소 의도 예시는 개발과 검증용이다. 사용자 문구로 복사하지 않는다.
- 힌트는 사용자가 요청할 때 짧게 제공한다. 자동으로 다음 정답 행동을 알려 주거나 단계별 해법을 펼치지 않는다.

## 한 줄은 죽음을 건너 쌓인다

모든 장의 기본 흐름은 1장과 같다. 장 입구에서 출발하면 적용되는 메모를 위에서부터 실행하고, 적용되는 메모가 없으면 용사가 눈앞의 첫 장애물이나 접근 지점까지 기본 전진한다. 기본 전진도 일반 행동과 같은 세계 변화·애니메이션·기록을 남기며 실패를 안전한 정지로 되돌리지 않는다.

죽음 결과를 본 뒤 다음 출발을 고르면 장 입구로 부활하고 정확히 한 줄을 쓸 기회를 얻는다. 확인한 문장은 새 기억으로 추가되어 다음 생의 모든 장면에서 유지되고, 화면 위쪽의 높은 우선순위부터 적용된다. 사용자는 출발 전에 순서를 바꿀 수 있다. 삭제는 죽은 뒤에만 가능하고 지우개를 먼저 쓰며, 지우개가 없을 때의 비용도 1장과 같은 공유 규칙을 따른다. 살아 있는 동안 장면을 넘었다는 이유로 무료 작성권·삭제권·새 메모장을 주지 않는다.

사용자는 자연스러운 짧은 한국어로 의도를 적는다. 정답 문구나 고정 동사 버튼을 외우게 하지 않는다. 초반은 한두 의도로 끝나며, 후반에도 긴 절차나 수치 계산을 해법의 조건으로 만들지 않는다. 같은 상태와 같은 의도는 같은 결과를 낸다. AI는 의도를 공개된 세계의 행동으로 해석하고 시뮬레이션이 결과를 결정한다. API가 없을 때 실제 AI처럼 보이는 가짜 응답을 제공하지 않는다.

한 메모가 뒤 장면에서도 같은 뜻으로 작동해야 할 때 해석 결과는 장면 전용 ID 대신 저작된 공개 명사 범주(`publicKind`)와 공개 조건을 함께 보관한다. 현재 장면에서 그 범주가 하나면 새 대상에 다시 결합하고, 없으면 그 메모는 잠들며, 둘 이상이면 실행 전에 어느 대상인지 확인한다. 내부 `properties.kind`와 숨은 연결·미래 상태를 공개 범주로 자동 복사하지 않는다.

명확하지 않은 대상이나 해석은 실행 전에 짧게 확인하고 무료로 고칠 수 있다. 이 예외를 모든 입력에 적용하는 승인 단계로 만들지 않는다. 실패한 접촉과 멈춘 이유는 짧은 세계 반응으로 보여 준다.

## 한 생과 다시 해 보기

2~10장에서도 한 생은 장 입구에서 시작해 성공하거나 죽을 때까지 이어진다. 장면 전환은 메모·우선순위·지우개·죽음 수·시도 번호·논리 tick·공개 관찰 기록을 유지한다. 새 장면의 공간은 저작된 시작 배치로 바꾸되 같은 생을 새 시도로 만들지 않는다. 일반 장면과 10장의 세 봉인은 부활 지점이 아니다.

죽으면 해당 생의 장면 완료 목록을 비우고 장 입구의 물리 상태로 돌아간다. 실패한 행동과 환경 반응, 어느 장면까지 갔는지, 부활과 새 메모는 연대기에 남긴다. 장을 끝낸 기록은 별도 보존하며 예전 `quiet-v1` 저장을 `shared-v1` 완료로 꾸미지 않는다.

### 도입의 무료 학습과 본편 인계

1장은 기존 네 이동 행동과 4개 도입+8개 방, 총 12개를 유지한다. 별도 물건 조작이나 새 위험을 추가하지 않는다. 2~10장은 물건·대기·상태·협력·관찰을 추가하되 메모장과 생명 주기는 같은 공유 코드로 실행한다. 장면 콘텐츠가 메모 누적, 우선순위, 지우개, 죽음 보상, 입구 재시작을 우회하거나 별도 학습 메모장을 만들 수 없다.

## 이야기와 음악

모루, 배달할 편지, 등지기와의 동행, 마지막 편지의 기존 의미를 유지한다. 주인공의 크림색 몸·민트 후드·금빛 달 장식과 장별 장소의 분위기를 보존한다. 이야기를 건너뛰어도 보이는 공간과 짧은 목적만으로 진행할 수 있다.

이야기 소품은 완료 뒤 짧은 선택 장면에 둔다. 필수 퍼즐의 물체 수를 늘리거나 숨은 조건을 만들지 않는다. 편지는 주머니의 서사 소품이며 무게·슬롯·소모 자원이 아니다. 마지막 문은 동료와 함께 지난 뒤 기존 편지 결말을 보여 준다.

### 음악과 실제 장치 신호

각 장은 하나의 모티프와 정서를 유지하고 장면에 따라 음색을 조금 바꾼다. 66장면에 서로 다른 곡을 요구하지 않는다. 음악은 실제 사건의 시계나 정답 단서가 아니다. 장치 소리와 음악을 구별하고 음소거에서도 모든 인과를 볼 수 있어야 한다. 실패 때 곡을 처음부터 다시 울리거나 실패 벌점처럼 불협화음을 넣지 않는다. 감소 모션에서는 흔들림·입자를 줄이고 필수 자세와 상태 변화를 남긴다.

## 검증 기준

- 현재 캠페인은 1장 12개, 2~10장 각 6개, 총 66개 장면으로 문서·카탈로그·실제 진행이 일치한다.
- 960×500에서 전체 배치와 행동 결과가 한눈에 들어오며 가로 넘침이나 물체 목록 화면이 없다.
- 내부 데이터가 사용자 UI로 새지 않고, 입장 목적 한 문장은 해결 방법을 말하지 않는다.
- 첫 장면에서 무엇이 문제인지, 내 행동 뒤 무엇이 달라졌는지 설명 패널 없이 읽힌다.
- 자연어 해석과 실제 행동 대상이 일치하고 실패는 한 번 기록된 뒤 장 입구의 다음 생과 한 줄 작성권으로 이어진다.
- 2~10장의 54개 장면은 장 입구에서 준비한 누적 메모장으로 순서대로 재생할 수 있고 장면 전환에서 메모·tick·시도 번호가 초기화되지 않는다.
- 필요한 검증은 실제 장면·저장·입력 흐름까지 확인한다. 코드 테스트 통과를 사람의 재미나 직관성 검증으로 표현하지 않는다.
