# 플레이 계약 v4 설계안 — 공간으로 유도하고 행동으로 설명하기

이 문서는 다음 개편의 제작 기준이다. 현재 실행 코드는 `spatial-v1`이며, 구현 위치와 자동화·화면 확인 범위는 [공간 실행기 v4](../spatial-implementation.md)에 구분한다. 아래 연출 세부와 사람의 플레이 검증을 모두 마쳤다는 뜻은 아니다. 1장의 메모 누적·우선순위·죽음 뒤 한 줄·지우개·입구 재시작 계약을 공용 코어 정책·UI·재생 모듈로 2~10장까지 이어 간다. 장 콘셉트·모루·편지·등지기·장별 음악과 후속 54개 장면의 학습 주제를 유지하되, 공간·오브젝트 구성·성공 판정은 이 설계에 맞춰 재검토한다. 장면마다 메모장을 비우고 무료 한 줄을 받던 `quiet-v1` 규칙은 폐기되었으며 현재 요구사항이 아니다.

## 공간이 먼저 설명한다

- 기준 화면은 **960×500 고정 구도**다. 화면 크기에 맞춘 전체 비율 축소는 허용하지만 확대 조작·카메라 이동·가로 스크롤로 대상 찾기를 요구하지 않는다.
- 한 장면은 하나의 공간 상황, 하나의 목표, 하나의 새 개념 또는 이미 배운 한 관계의 재회다. 복잡해지면 별도 장면으로 나눈다.
- 2~4장은 도착점·위험·조작물·관찰 대상을 모두 합해 **최대 4개**다. 5~10장도 4개를 기본 상한으로 삼고 현재 54개 장면은 모두 이를 지킨다. 다섯 번째 요소가 꼭 필요하면 먼저 장면 분할을 검토하고 독립 근거를 남긴다.
- 용사와 동료는 위 수에서 제외해도 각각의 역할이 인지 부담임을 고려한다. 둘이 함께 있어야 할 이유가 없는 장면에서는 동료에게 별도 판단을 맡기지 않는다.
- 조작 가능한 연결 부품을 배경이나 복합 장치 하나로 묶어 수를 숨기지 않는다. 일반 바닥은 배경이지만 위험한 틈과 전용 이동 발판은 센다.
- 요소는 높이·거리·길·가림·접촉을 가진 공간에 놓는다. 같은 크기의 물체 카드나 아이콘을 한 줄로 세운 퍼즐, 물체 목록 갤러리로 대체하지 않는다.

## 의도한 풀이를 공간으로 유도한다

초반이라는 이유로 학습 주제를 건너뛰는 지름길을 허용하지 않는다. 최초 장면도 물체의 크기·자리·접촉 관계를 보고 의도한 행동을 발견해야 한다. 그렇다고 정해 둔 동사나 예문을 입력했는지로 성공을 판정하지 않는다. 장별 최소 의도 예시는 유일한 정답이 아니다.

- 점프 거리·높이, 몸이 통과할 틈, 착지 지지면, 머리 위 여유는 공통 규칙이다. 장마다 보이지 않는 점프 금지나 임의의 힘 제한을 붙이지 않는다. 수치는 제작 데이터에만 두고 용사의 몸·상자·바닥과의 크기 비교로 읽히게 한다.
- 출구 좌표로 이동시키는 것만으로 이동을 끝내지 않는다. 현재 위치부터 이동 경로, 최초 접촉, 착지와 지지 상태를 순서대로 계산한다. 렌더링 바닥과 판정 바닥은 같은 배치 데이터를 사용한다.
- 직접 점프로 해결되면 안 되는 곳은 실제로 멀거나 높아야 한다. 손잡이를 놓으면 닫히는 문, 둘이 도착해야 하는 공간처럼 물리 관계와 공동 목표가 필요성을 만든다. 화면에 없는 장애물이나 완료 시점의 숨은 행동 이력 검사로 우회를 막지 않는다.
- 자연스러운 다른 행동이 같은 물리 결과를 만든다면 인정한다. 그 결과가 학습을 무의미하게 만들면 그 행동을 금지하기보다 배치를 다시 설계한다. 모든 대안을 억지로 실패시키는 것은 목표가 아니다.
- 천장·벽은 실제 이동 경계일 때 배경 지형으로 쓸 수 있다. 별도 관찰·조작·타이밍 판단을 요구하는 위험을 배경 장식이라고 부르며 4개 상한에서 제외하지 않는다.
- 한 장 안에서 장면이 바뀌어도 같은 물체 범주와 행동 의미는 일관돼야 한다. 반복 메모의 적용 대상·우선순위를 플레이어가 예측할 수 있어야 한다.

## 물체마다 행동과 결과를 보여 준다

각 장면 문서의 연출은 **신호 → 접근 → 접촉 또는 회피 → 물체 변화 → 결과**를 명시한다. 정지 화면의 장치와 입력 후의 행동을 같은 물리 상태에서 그린다. 연출이 아직 일어나지 않은 접촉·사망·완료를 앞질러 보여 주지 않는다.

| 관계 | 필요한 연출 | 금지하는 생략 |
| --- | --- | --- |
| 상자·닫힌 문에 막힘 | 실제 장애물 앞까지 걷기, 발 멈춤, 손이나 어깨 접촉, 짧은 반동 | 출발 자리에서 사망하거나 장애물 반대편으로 순간이동 |
| 틈·높은 턱 | 발 구름, 점프 궤적, 모서리 접촉 또는 착지·추락 | 목표 좌표에 도착한 뒤 텍스트로만 실패 설명 |
| 뜨거운 김·열판 | 분출 전 떨림·김 또는 열기의 변화, 접촉 시 움츠림·후퇴, 계속 위험에 노출될 때의 붕괴 | 닿기도 전에 공용 사망 효과 하나로 처리 |
| 집게·종추·회전날개 | 장치의 실제 주기, 용사 접근과 장치의 교차, 충격·밀림·추락의 연속 | 대기 명령 유무만 검사해 성공/사망 |
| 물·발판·받침 | 수위·잠김, 발판의 눌림·복원, 무게가 실리는 순간과 지지 상실 | 물체가 움직여도 용사와 바닥 상태는 그대로 두기 |
| 손잡이·줄·동료 | 손의 접촉, 당김과 장력, 상대 이동, 놓을 때 장치 복귀 | 잡기/놓기 상태만 바뀌고 물체나 손은 정지 |
| 빛·안개·관찰 | 고개와 시선, 빛이 닿는 범위, 새로 드러나는 길의 윤곽 | 관찰 명령을 입력했다는 이유만으로 안전 통과 허용 |

연출 구현은 공용 걷기·점프·접근·접촉·반동·낙하·부활을 조합하고 물체는 장치별 상태 전이와 효과를 제공한다. 장별 별도 플레이 화면이나 복사한 실행기를 만들지 않는다. 감소 모션에서도 접촉 위치·물체 상태 변화·결과는 남기며, 음소거에서도 주기를 읽을 수 있어야 한다.

단단한 물체에 막힌 것과 죽음은 구분한다. 비치명적인 접촉은 실제 접촉 위치에서 멈추고 기존 `blocked` 흐름으로 이어진다. 자유로운 문장 수정·무료 재시작을 새로 주지 않으며, 새 메모가 필요하면 기존 포기·부활과 작성권 정책을 따른다. 실제 사망은 접촉·추락 등 원인이 있는 전이를 재생한 후 한 번만 기록한다. 1장 도입의 기존 무료 학습 예외는 그대로 유지한다.

## 사용자 문구와 내부 명세를 나눈다

입장할 때 **해야 할 일만 한 문장으로 한 번** 말한다. 장면마다 목적이 다르면 그 목적을 바꿔 말한다. 예를 들어 편지와 함께 회랑을 건너기, 빵 꺼내기, 등지기와 합류하기를 짧게 알린다. 이를 닫기 위한 팝업이나 확인 버튼은 없다.

- 목표는 무엇을 이루는지만 말한다. 어떤 물건부터 만질지, 어떤 조건을 만족할지, 해결 순서는 알려 주지 않는다.
- 이름이 없으면 대상을 구분하기 어려운 사물에만 짧은 이름을 붙인다. 물체별 목표 설명·상세 속성·사용법은 표시하지 않는다.
- 무게·압력·범위·슬롯·내부 상태값·조건표·해결 체크리스트·상태 요약 패널·정답 예시를 사용자 화면에 내보내지 않는다.
- 모양, 위치, 움직임, 손의 접촉, 줄의 장력, 물의 흐름과 행동 뒤 변화를 통해 인과를 읽는다. 색만으로 구별하지 않는다.
- 장 문서의 요소 수, 역할, 완료 판정, 최소 의도 예시는 개발과 검증용이다. 사용자 문구로 복사하지 않는다.
- 힌트는 사용자가 요청할 때 짧게 제공한다. 자동으로 다음 정답 행동을 알려 주거나 단계별 해법을 펼치지 않는다.

## 한 줄은 죽음을 건너 쌓인다

메모 선택의 기준은 [공통 메모 수칙](../game-rules.md)이다. 메모는 일회성 작업이 아니다. 모든 행동 판단마다 위에서부터 현재 조건을 다시 검사하고 처음 맞는 수칙 하나를 실행한다. 한 번 실행해도 소모하지 않으며, 적용할 수칙이 없을 때만 그 자리에서 멈춘다. 시스템이 전진이나 이동 지시를 덧붙이지 않는다. 계속 걷게 하려면 사용자가 전진 지시를 남겨야 한다. 지시가 없어 정지하는 것은 사망이 아니며 위치·데스·작성권을 임의로 바꾸지 않는다. 이미 지시한 발판 탑승과 명시적 대기는 그 행동에 따른 환경 변화를 이어간다.

죽음 결과를 본 뒤 다음 출발을 고르면 장 입구로 부활하고 정확히 한 줄을 쓸 기회를 얻는다. 확인한 문장은 새 기억으로 추가되어 다음 생의 모든 장면에서 유지되고, 화면 위쪽의 높은 우선순위부터 적용된다. 사용자는 출발 전에 순서를 바꿀 수 있다. 삭제는 죽은 뒤에만 가능하고 지우개를 먼저 쓰며, 지우개가 없을 때의 비용도 1장과 같은 공유 규칙을 따른다. 살아 있는 동안 장면을 넘었다는 이유로 무료 작성권·삭제권·새 메모장을 주지 않는다.

사용자는 자연스러운 짧은 한국어로 의도를 적는다. 정답 문구나 고정 동사 버튼을 외우게 하지 않는다. 초반은 한두 의도로 끝나며, 후반에도 긴 절차나 수치 계산을 해법의 조건으로 만들지 않는다. 같은 상태와 같은 의도는 같은 결과를 낸다. AI는 의도를 공개된 세계의 행동으로 해석하고 시뮬레이션이 결과를 결정한다. API가 없을 때 실제 AI처럼 보이는 가짜 응답을 제공하지 않는다.

한 메모가 뒤 장면에서도 같은 뜻으로 작동해야 할 때 해석 결과는 장면 전용 ID 대신 저작된 공개 명사 범주(`publicKind`)와 공개 조건을 함께 보관한다. 현재 장면에서 그 범주가 하나면 새 대상에 다시 결합하고, 없으면 그 메모는 잠들며, 둘 이상이면 실행 전에 어느 대상인지 확인한다. 내부 `properties.kind`와 숨은 연결·미래 상태를 공개 범주로 자동 복사하지 않는다.

명확하지 않은 대상이나 해석은 실행 전에 짧게 확인하고 무료로 고칠 수 있다. 이 예외를 모든 입력에 적용하는 승인 단계로 만들지 않는다. 실패한 접촉과 멈춘 이유는 짧은 세계 반응으로 보여 준다.

## 한 생과 다시 해 보기

2~10장에서도 한 생은 장 입구에서 시작해 성공하거나 죽을 때까지 이어진다. 장면 전환은 메모·우선순위·지우개·죽음 수·시도 번호·논리 tick·공개 관찰 기록을 유지한다. 새 장면의 공간은 저작된 배치로 전환하되 같은 생을 새 시도로 만들지 않는다. 문서에서 이어지는 물체를 명시한 구간(예: 4-5→4-6의 풍로, 6-2→6-3의 등불)은 직전 결과를 인계한다. 대안 풀이로 물체의 위치가 달라졌다면 그 차이도 인계하며, 다음 장면의 기본 그림에 맞추려고 물체를 임의로 옮기지 않는다. 일반 장면과 10장의 세 봉인은 부활 지점이 아니다.

죽으면 해당 생의 장면 완료 목록을 비우고 장 입구의 물리 상태로 돌아간다. 실패한 행동과 환경 반응, 어느 장면까지 갔는지, 부활과 새 메모는 연대기에 남긴다. 장을 끝낸 기록은 별도 보존하며 예전 `quiet-v1` 저장을 `shared-v1` 완료로 꾸미지 않는다.

### 1장의 통합된 여섯 장면

새 1장은 기존 네 이동 행동을 여섯 장면에서 익힌다. 서사 프롤로그 읽기와 SKIP은 모두 1-1로 들어간다. 첫 입력부터 같은 메모·우선순위·지우개·데스·연혁을 1-6까지 사용한다. 별도 네 단계 온보딩이나 중간 메모 초기화, 강제 사망·삭제 실습은 없다. 우선순위와 지우개는 실제 메모 사용 시 짧게 안내한다. `layoutVersion`이 없거나 1인 진행 저장은 기존 도입과 여덟 방을 계속 사용하고, 과거 완료 기록은 이전 좌표로 검증한 뒤 장별 완료·최고 기록 요약으로 전환한다. 새 시작·초기화는 `layoutVersion: 3`의 여섯 장면을 사용한다. 2~10장은 물건·대기·상태·협력·관찰을 추가하되 메모장과 생명 주기는 같은 공유 코드로 실행한다.

## 이야기와 음악

모루, 배달할 편지, 등지기와의 동행, 마지막 편지의 기존 의미를 유지한다. 주인공의 크림색 몸·민트 후드·금빛 달 장식과 장별 장소의 분위기를 보존한다. 이야기를 건너뛰어도 보이는 공간과 짧은 목적만으로 진행할 수 있다.

이야기 소품은 완료 뒤 짧은 선택 장면에 둔다. 필수 퍼즐의 물체 수를 늘리거나 숨은 조건을 만들지 않는다. 편지는 주머니의 서사 소품이며 무게·슬롯·소모 자원이 아니다. 마지막 문은 동료와 함께 지난 뒤 기존 편지 결말을 보여 준다.

### 음악과 실제 장치 신호

각 장은 하나의 모티프와 정서를 유지하고 장면에 따라 음색을 조금 바꾼다. 60장면에 서로 다른 곡을 요구하지 않는다. 음악은 실제 사건의 시계나 정답 단서가 아니다. 장치 소리와 음악을 구별하고 음소거에서도 모든 인과를 볼 수 있어야 한다. 실패 때 곡을 처음부터 다시 울리거나 실패 벌점처럼 불협화음을 넣지 않는다. 감소 모션에서는 흔들림·입자를 줄이고 필수 자세와 상태 변화를 남긴다.

## 검증 기준

- 새 캠페인은 1~10장 각 6개, 총 60개 장면이다. 기존 진행 저장과 완료 기록은 이전 번호를 유지한다.
- 960×500에서 전체 배치와 행동 결과가 한눈에 들어오며 가로 넘침이나 물체 목록 화면이 없다.
- 내부 데이터가 사용자 UI로 새지 않고, 입장 목적 한 문장은 해결 방법을 말하지 않는다.
- 첫 장면에서 무엇이 문제인지, 내 행동 뒤 무엇이 달라졌는지 설명 패널 없이 읽힌다.
- 자연어 해석과 실제 행동 대상이 일치하고 실패는 한 번 기록된 뒤 장 입구의 다음 생과 한 줄 작성권으로 이어진다.
- 2~10장의 54개 장면은 장 입구에서 준비한 누적 메모장으로 순서대로 재생할 수 있고 장면 전환에서 메모·tick·시도 번호가 초기화되지 않는다.
- 필요한 검증은 실제 장면·저장·입력 흐름까지 확인한다. 코드 테스트 통과를 사람의 재미나 직관성 검증으로 표현하지 않는다.

## 개편 구현 후 통과해야 할 확인

1. 각 장면에서 의도한 풀이와 자연스러운 대안, 무조건 직진, 출구로 바로 점프, 반복 점프, 무조건 기다리기를 비교한다. 테스트 통과를 위해 원래 예문만 맞추지 않는다.
2. 장 입구부터 같은 단순 메모를 유지했을 때 서로 다른 학습 주제를 모두 생략하는지 확인한다. 획일적인 전략이 장 전체를 해결하면 배치를 다시 본다.
3. 막히는 위치·착지·물체 충돌·지지 상실이 화면과 같고, 직진 실패도 실제 접근을 거치는지 재생 중간 프레임에서 확인한다.
4. 오브젝트별 실패 연출과 성공 연출, 반복 재생·일시정지·감소 모션이 같은 최종 상태를 가리키는지 확인한다.
5. 장 입구 재시작·메모 누적·우선순위·지우개·작성권과 기존 1장 회귀를 함께 확인한다. 장면 단독 정답 검사만으로 완료를 선언하지 않는다.
6. 사람이 설명 없이 의도한 행동을 떠올리는지, 실패 이유를 화면만 보고 말할 수 있는지 확인한다. 자동 실행 결과와 체감 난이도를 구분한다.

### 첫 접촉의 짧은 발견

새 1장의 여섯 장면과 2~10장의 각 6개 장면에서 실제 실패 뒤 아직 배우지 않은 물리 발견 하나를 짧게 보여 준다. 기존 진행 저장의 도입과 여덟 방은 이전 경로를 유지한다. 후속 장은 현재 장의 전체 장면 이력을 검색한다. 충돌 재생이 끝난 다음 기존 피드백 안에 한 문장으로 붙이고, 같은 발견은 다음 생에도 반복하지 않는다. 물리 접촉 대상과 명령의 목적지는 구분한다. 상자를 향해 뛰다가 천장에 닿으면 천장에 대한 말을 한다. 사다리처럼 실제로 접근한 뒤 두 손이 필요해서 막히는 상호작용도 포함한다. 지시가 없어서 정지했거나 대상에 도달하지 못한 것만으로는 물체의 성질을 추측해 보여 주지 않는다. 낙하는 물체 접촉으로 꾸며내지 않고 장면의 실제 낙하 관측으로 처리한다. 정확한 명령·전체 풀이·내부 수치는 노출하지 않으며 AI를 추가 호출하지 않는다. 모바일에서는 이 피드백이 맵을 가리지 않게 맵 아래에 둔다.
