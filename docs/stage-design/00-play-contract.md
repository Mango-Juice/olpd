# 공통 설계 규칙 — 차근차근 몸으로 익히고 문장으로 잇기

> **2026-09-22 도입 개정 / 로컬 구현.** 통합 검증은 [구현 기록](../campaign-implementation.md)을 참고한다. 재미·플레이타임은 실측하지 않았다. 문서의 확장 규칙과 현재 코드 동작을 구분하며, 예문은 의도 검토용이다.

## 기존 1장과의 경계

1-1~1-4는 전진·점프·숙이기·우회를 하나씩 몸으로 해 보는 새 정식 도입이다. 1-5~1-12의 기존 8방은 원래 배치·순서·판단점·단일 행동 의미를 유지한다. 기존 후반 방에서 처음 배우던 몸동작은 이제 도입 뒤 조건 확장·예외 적용으로 돌아온다. 물건 조작·다중 행동·구간별 발견 한 줄은 기존 8방에 넣지 않는다.

새 도입이 기존 체험형 프롤로그를 대체하므로 강제 추락·부활·삭제 연습을 연이어 재생하지 않는다. 서사 프롤로그와 그 SKIP은 유지하되 이야기를 건너뛰는 것과 학습 완료는 별개다. 신규 플레이어는 정식 도입을 순서대로 완료하고, 기존 본편 진행 저장은 입문 면제로 보존한다. 면제에 가짜 플레이·완료 연혁을 쓰지 않는다. 이미 받은 프롤로그 메모 두 줄이나 기존 본편 메모·장치 상태를 지우지 않는다.

## 장·스테이지와 공용 화면

한 스테이지는 별도 입장 배치, 한 문장 목표, 실제 물리 행동, 완료 조건과 다음 장면을 갖는다. 도입은 팝업·툴팁·선택 연습장이 아니라 캠페인의 필수 진행이다. 예를 들어 4장은 도입 4-1~4-2 뒤 기존 퍼즐 4-3~4-7을 진행한다. 모든 장의 표시 번호는 1부터 연속이고 코드 ID와 옛 번호 대응은 각 장 표에 남긴다. 기존 저장의 식별자를 화면 번호로 그대로 덮어쓰지 않는다.

첫 도입에는 실제로 조작·관찰·도달할 대상 한두 개와 관계 하나만 배치한다. 이동 목표도 대상 목록에 적는다. 용사, 고정 지형, 장치의 연결 부품은 무엇이 실제로 보이는지 별도로 명시해 숫자만 줄이지 않는다. 협력처럼 주체와 도착 지점이 함께 필요한 단계는 세 대상을 쓸 수 있으나, 배운 두 관계를 한꺼번에 새로 설명하지 않는다. 이 기준은 후기 종합 퍼즐의 전역 객체 수 상한이 아니다.

아직 배우지 않은 장치·자원·경로는 장면에 놓지 않는다. 접힌 목록이나 어두운 실루엣 뒤에 남겨 두는 방식으로 학습량을 줄였다고 보지 않는다. 다음 정식 장면에 들어가 새 대상 하나를 실제로 만난다. 후반 9·10장은 이미 익힌 지지·상태·사건·기류를 해당 공간에서 짧게 확인할 뿐 새 규칙이나 반복 강의를 만들지 않는다.

프롤로그·1장·후속 장은 헤더, 종이 메모장, 입력창, 단계별 실마리, 진행 표시를 공유한다. 필요한 사실과 한 문장 목표는 처음부터 읽힌다. 자세한 물성 설명은 선택 관찰로 제공하되 실제 첫 배치를 줄이는 일을 대신하지 않는다. 실마리는 같은 위치에서 사용자가 한 단계씩 요청하고, 키보드와 보조기술로도 관찰 가능해야 한다.

물체 이름은 생김새와 역할을 바로 떠올릴 수 있는 일상어를 쓴다. 색·문양·수치는 구분이나 풀이에 필요할 때만 추가한다. 낯선 장치 이름을 외우는 대신 직접 작동시켜 관계를 알아간다.

## 도입의 무료 학습과 본편 인계

- **도입 시작:** 각 단계는 독립 시작 스냅샷과 임시 한 줄을 갖는다. 확정·실행·수정·삭제·재시작은 횟수 제한 없이 무료다. 문장 추가 기회를 얻으려고 죽거나 기다리지 않는다. 같은 상태의 같은 의도는 같은 결과를 낸다.
- **실패와 완료:** 잘못된 물리 행동도 화면에 결과를 내되 안전 받침·멈춤·지역 복구로 돌아온다. 종, 본편 사망, 지우개, 점수에 가산하지 않는다. 실패나 예문 열람을 완료 조건으로 강요하지 않는다. 각 카드의 물리 목표를 달성해야 다음 정식 장면을 연다.
- **진행 저장:** 완료 번호와 시도한 임시 문장 원문은 도입 기록으로 남고 본편 연대기·활성 메모와 구분한다. 중단하면 현재 단계의 스냅샷·진행에서 재개한다. 앞 도입 재생은 선택이며 본편 방문 장부를 갱신하지 않는다.
- **도입 간 연결:** 명시한 직결 단계(6-1→6-2, 9-1→9-2)는 앞 성공 상태를 다음의 시작 스냅샷에 넣는다. 지역 복구는 그 스냅샷을 복원한다. 그 밖의 단계는 카드의 고정 시작 상태를 쓴다. 이전 임시 지침을 자동 활성화해 다음 퍼즐을 대신 풀지 않는다.
- **본편 인계:** 마지막 도입 완료 뒤 기존 첫 구간의 원래 배치로 전환하고, 도입 이후를 장의 본편 복귀점으로 저장한다. 임시 도구·임무·관찰 사실·무료 수정 권한은 넘어오지 않는다. 도입 원문은 참고 기록으로 읽을 수 있으나 활성 메모에 자동 복사하지 않는다.
- **1장 인계:** 신규 플레이는 1-5에서 빈 본편 메모, 무료 첫 작성 1회, 사망·삭제 가산 0, 지우개 2개로 시작한다. 이후 1-6~1-12의 최초 도달에는 추가 무료 줄을 주지 않는다. 실패는 1-5로 돌아가며 기존 네 행동·메모 경제를 따른다.
- **2~9장 인계:** 기존 첫 구간의 최초 발견 기회 1회와 장 첫 줄은 같은 지급이다. 이전에 완료한 장의 본편 메모만 인계 시 무료 복사할 수 있고, 첫 본편 출발 뒤에는 잠긴다. 도입 원문을 복사하는 별도 공짜 슬롯은 없다. 지우개는 본편 시작에 2개, 종은 도입 때문에 늘지 않는다.
- **10장 인계:** 10-3이 봉인 I의 첫 복귀점이며, 봉인 II는 10-5, 봉인 III는 10-7이다. 실패는 현재 봉인으로 돌아가고 도입은 반복하지 않는다. 세 봉인·기존 여섯 비트의 관계는 보존한다.
- **재방문과 호환성:** 도입 재생·무료 지역 복구는 본편 무료 첫 줄, 지우개, 종, 관측 사실을 새로 만들거나 복구하지 않는다. 본편 입장 완료 플래그와 구간 방문 장부는 도입 복구 밖에 저장한다. 기존 본편 진행/완료 저장에는 입문 면제만 붙이고 기존 메모·관찰·장치를 보존한다.
- **선택 연습:** 정식 도입을 마친 뒤 같은 장치를 다시 만지는 기능이다. 자동 진입·진행 보상·필수 선수 지식이 없으며 생략해도 후속 퍼즐을 풀 수 있다. 특히 쐐기 지지는 선택 연습이 아닌 7-4에서 반드시 경험한다.

> **기존 기획과 충돌한 지점:** 장 시작으로 통째로 되감으면 매 실패마다 해당 장의 도입까지 반복하게 될 수 있었다. 이제 도입 완료 경계와 본편 시작 스냅샷을 분리한다. 기존 “무료 안전 교습” 표현도 도입의 무제한 수정과 본편의 단순 미완료를 나누어 해석한다. 이 경계는 로컬 구현됐고 통합 검증은 진행 중이다.

## 1. 자유의 범위: 표현은 열고, 세계의 법칙은 고정한다

자유로운 입력을 무제한 마법으로 처리하지 않는다. 화면 속 물체에는 일관된 성질과 상호작용이 있다. 같은 받침은 다리를 지지하고, 문을 받치고, 물건을 높일 수 있다. 쓰임새마다 따로 숨은 정답 표식을 붙이지 않는다.

물건을 살펴보면 재질, 이동 가능 여부, 잡을 곳, 닿는 범위, 현재 상태를 알 수 있다. 수치가 중요하면 눈금·칸·추와 텍스트로 확인한다. 반대로 풀기에 필요 없는 무게 숫자를 외우게 하지 않는다. 도구의 관계를 발견하는 것이 퍼즐이고, 해당 관계가 지원되는지 추측하는 것은 퍼즐이 아니다.

배달할 편지는 용사의 몸에 매단 전용 주머니에 있으며 퍼즐의 손 한 칸·물건 고리 두 칸을 차지하지 않는다. 모험 중에는 내려놓는 자원이 아니고 이 제약은 관찰 설명에 표시한다. 편지의 소유·위치·젖음 상태는 저장하며 용사와 함께 움직인다. 마지막 배달문에서 편지를 가진 용사가 도착했는지 확인하고, 클리어 후 엔딩에서 편지를 펼친다.

손 한 칸이 비어 있으면 작은 물건 하나를 손에도 들 수 있다. 따라서 큰 물건 하나와 작은 물건 둘, 또는 작은 물건 셋을 운반할 수 있다. 이는 물건 ID나 집은 순서에 따라 달라지지 않는다. 세 번째 작은 물건을 손에 든 채 큰 물건까지 들거나 고리 두 칸에 작은 물건 셋을 걸 수는 없다. 장별로 공개한 더 좁은 제약(씨앗 한 손, 등지기의 작은 물건 하나)은 해당 장치와 주체에 적용한다.

- “상자를 밀어 발판 아래에 둬”, “발판 밑까지 나무 상자를 옮겨”는 같은 의도로 인정한다.
- “돌아가”, “통을 세워”, “멈춰”처럼 대상이나 상태가 여러 뜻이면 원문의 해당 부분을 짚어 다시 쓰게 한다. 정답 동사 목록을 내밀지 않는다.
- “문을 열어”는 눈앞의 손잡이 하나를 여는 일이라면 충분하다. 여러 기계를 해결해야 한다면 “무엇을 이용해 열지 아직 모르겠어”라고 설명한다. AI가 플레이어 대신 퍼즐 전체를 풀지 않는다.
- “안전하게”, “잘”, “알아서”는 새로운 능력이나 미래 지식을 만들지 않는다. “안전하게 건너”만으로 최적 경로를 자동 탐색하지 않는다.
- 세계에 없는 비행·순간이동·무한 복제는 이해 가능한 요청이라도 실행 가능한 능력이 아님을 알려 준다. 생명을 소모해 알아내게 하지 않는다.
- 물리적으로 할 수 있는 행동을 잘못된 곳에서 하면 실제로 실패할 수 있다. 무거운 돌을 얇은 판자에 올리는 일은 해석 오류가 아니며, 판자의 휨과 파손 원인을 보여 준다.

상호작용 하나를 추가할 때 연관 장면도 함께 확인한다. “이 방의 상자만 문을 못 받친다”처럼 제작자의 의도 밖 해법을 막기 위한 예외는 만들지 않는다. 합리적인 우회 풀이가 성립하면 통과시킨다. 세계의 재질·크기·연결 구조로 불가능한 것은 그 이유가 보이게 한다.

## 2. 문장 UI와 해석 결과

입력창은 자유 문장 한 줄이다. 장식적으로 “다음에는…”을 붙일 수 있지만 조사나 빈칸 종류를 강제하지 않는다. 초반에는 짧은 문장으로 충분하고, 후반에는 “A면 B하고, C가 될 때까지 유지한 뒤 D해”도 가능하다. 행동 수를 장별로 해금하지 않는다.

목표는 200자 안팎에서도 편하게 작성하는 UI이며 80자 제한은 재검토한다. 글자 수를 퍼즐 자원으로 삼지 않고, 문장이 과도하게 길어지는 방은 중간 목표를 나눈다. 구현의 안전 제한이 필요해도 조용히 잘라 실행하지 않는다.

- 입력 전에는 현재 장면의 **사실**과 달성할 **목표**를 보여 준다. 목적에 필요한 핵심 시야를 가리지 않는다.
- 첫 입력과 새 문장 관계를 처음 쓸 때 “통을 먼저 놓고 → 올라탄 뒤 → 물가에서 내릴게”처럼 실행 의도를 짧게 되읽는다. 이후 같은 관계는 빠르게 진행한다.
- 미리보기는 플레이어의 의도를 확인한다. 아직 관찰하지 않은 경로나 최적 해법, 미래 실패 여부를 알려 주는 자동 풀이기가 아니다.
- “잡아 둬”와 “한 번 당겨”처럼 결과가 다른 해석은 확정 전에 확인한다. 표현을 명확히 하는 수정에는 작성 기회·지우개·종 횟수를 쓰지 않는다.
- 알려진 물체를 가리키는 비유·별칭·동의어는 연결할 수 있다. 물체 자체나 능력을 새로 창작하지 않는다.
- 모델 응답 지연·통신 오류·해석 실패는 게임의 사망이 아니다. 같은 확정 문장과 같은 상태는 같은 결과를 내야 한다.

## 3. 실행의 의미

### 대상과 범위

지침은 현재 보이거나 현재 시도에서 확인한 대상을 가리킨다. 목표가 다른 방에 있을 때는 이 방의 물체에 멋대로 대입하지 않는다. “상자”가 둘이면 위치·재질·표식을 확인한다. 한 대상을 정한 뒤 이동했다고 중간에 다른 상자로 바뀌지 않는다.

지침의 적용 범위는 물체 또는 상황 중심이다. 방 번호 암기가 정답이 되는 지시를 필수로 요구하지 않는다. 장 번호나 이름으로 한정하는 표현도 원하면 허용한다.

### 순서와 지속

“밀고 올라가”는 앞 행동의 완료 뒤 다음 행동을 시작한다. 한 번 시작한 절차는 다음 행동 경계에서 상태를 확인하며 이어 간다. 첫 조건이 사라졌다는 이유만으로 성공 중인 절차를 처음부터 다시 시작하지 않는다. 실행이 끝난 지침은 같은 상황에서 무한 반복하지 않고 새로운 사건·재진입을 기다린다.

“누르고 있어”는 해당 주체가 자리를 유지하는 행동이다. 같은 주체에게 이동을 지시하면 유지가 끝난다. 이를 모순된 명령이라며 임의로 둘 다 성공시키지 않는다. “인형이 누르는 동안 나는 건너”는 두 주체의 동시 행동이다. 인형의 능력·사거리도 먼저 보여 준다.

“문이 완전히 열리면”은 사건 기준이다. 실시간 키 입력이나 0.2초 단위 타이핑을 요구하지 않는다. 게임 내 이동 속도와 장치 주기가 안전 창을 결정한다. 3배속·일시정지·프레임 저하는 결과를 바꾸지 않는다.

### 여러 줄의 우선순위

현재 게임의 **화면 위쪽에서 먼저 적용되는 줄을 선택**하는 원리를 유지한다. 출발 전 순서 변경은 무료다. ‘새 줄이 무조건 우선’이라는 옛 규칙은 쓰지 않는다.

실행 중인 절차는 자기 차례를 이어 간다. 더 높은 줄이 명시적으로 경계하는 상황이 발생하면 다음 안전한 행동 경계에서 중단하고 그 줄을 따른다. 이미 공중에 뜬 몸을 순간이동시키지는 않는다. 중단된 절차를 자동으로 처음부터 반복하지 않고, 계속할 수 있는지와 중단 지점을 기록한다. 이런 중단이 필요한 장면에는 중단 가능한 발판이나 정지 공간을 마련한다.

일반 규칙과 예외 규칙이 겹치면 출발 전에 겹치는 관찰 조건을 보여 준다. 현재의 ‘적용 상황 전체가 같고 행동만 다르면 저장 거절’은 확장된 상태·순서·주체를 구분하도록 재설계해야 한다. 이 캠페인에서는 겹침 자체를 금지하지 않고, 가려지는 줄을 경고하며 플레이어가 우선순위를 정한다.

### 기억과 관찰

메모장의 **지침**은 되감아도 남고, 세계의 **관찰 사실**은 시도에 속한다. “무늬를 확인한 뒤 기억해”라는 지침은 유지되지만 이전 시도에서 본 ‘이번 화물은 오른쪽 선로’라는 사실은 현재 값으로 사용할 수 없다. 화면의 사실 기록에도 이전 시도 표식을 붙인다.

‘알 수 없음’과 ‘거짓’을 구별한다. 확인하지 못한 신호를 반대 신호로 취급하지 않는다. 관찰이 필요하면 그 자리에 가거나 시야를 확보하는 행위를 문장에 담는다. “기억해”만으로 보이지 않는 정답을 얻지 않는다.

## 4. 본편의 시도, 죽음, 메모장

다음 표는 2~10장 **도입 이후 본편**에 적용한다. 1장은 위 인계 후 기존 경제를 따른다.

| 항목 | 캠페인 계약 |
| --- | --- |
| 본편 첫 진입 | 기존 첫 구간의 안전 책갈피와 무료 한 줄 1회. 장 첫 지급과 중복 없음 |
| 새 본편 구간 첫 도달 | 목표·배치를 본 뒤 무료 한 줄 1회. 미사용 기회 누적 없음 |
| 발견 기회 보존 | 방문·사용 이력은 되감기 밖에 남음. 재방문·도입 재생으로 재지급하지 않음 |
| 일반 시도 | 확정된 지침으로 자동 진행. 유효 실패 또는 자진 되감기 한 번에 새 한 줄 기회 한 번 |
| 작성 기회 사용 | 새 줄 추가 또는 기존 한 줄 수정. 확정 줄 수정은 삭제 비용도 적용. 실행 전 해석 명료화는 무료 |
| 삭제 | 본편 시작 지우개 2개. 소진 후 한 줄 삭제·수정에 +3회 종 |
| 기존 지침 | 완료 장 본편 원본 보관. 현재 장 첫 본편 출발 전 필요한 줄 무료 복사. 도입 임시 노트는 참고 기록만 유지 |
| 재배치 | 출발 전 및 새 본편 구간 최초 안전 책갈피에서 무료. 실행·대기 중에는 변경하지 않음 |
| 장 체크포인트 | 도입 뒤 기존 첫 구간 시작. 물건·장치·현재 시도 사실을 그 스냅샷으로 초기화하며 도입 완료는 유지 |
| 재생 | 같은 지침·상태로 이미 통과한 본편 구간만 압축. 변경 영향이 있으면 재계산하고 변화 지점을 보여 줌 |
| 중단·교착 | 원인과 되감기를 제공. 단순 미완료·관찰·해석 오류는 사망이 아니며 새 작성 기회도 생성하지 않음 |
| 보스 | 10-3/10-5/10-7의 세 봉인 시작 체크포인트. 봉인 전환의 한 줄은 다음 비트 최초 발견 지급과 같은 1회 |

2~9장은 기존 본편 다섯 구간에 발견 기회 최대 5회, 10장은 기존 본편 여섯 비트에 최대 6회다. 도입 26개의 임시 노트는 이 수에 더하지 않는다. 신규 도입을 포함해 화면 단계 수가 늘어도 본편 메모·무료 지급 총량이 늘어나는 것은 아니다.

안전한 열린 길에서는 기본 전진하되, 지시 없는 상호작용·갈림길·새 위험 앞에서는 멈추고 이유를 알린다. 이는 2장 이후 규칙이며 기존 1장 8방의 기본 전진을 바꾸지 않는다. 본편에서 안전하게 멈춰도 확정 지침 수정은 공짜가 아니다. 최초 책갈피 기회를 이미 썼다면 자진 되감기 종 1회로 작성 기회를 얻는다. 단순 미완료를 즉사로 바꾸거나, 연속 새 개념 때문에 이 과정을 반복하게 만들지 않는다.

장의 기초 개념은 정식 도입에서 먼저 경험하고, 본편 대표 해법은 가져온 지침과 발견 한 줄로 표현 가능한지 점검한다. 본편의 한 문장을 도입에서 몰래 보관·자동 복사해 이 조건을 맞추지 않는다. 지우개·종은 도전 기록이지 콘텐츠 해금 화폐가 아니며, 실패 수로 스토리나 보스 난도를 바꾸지 않는다.

## 5. 퍼즐 카드의 공정성

모든 핵심 구간은 다음을 충족해야 한다.

1. **목표가 보인다.** 출구 도착, 물건 함께 운반, 장치 해제 중 무엇을 달성해야 하는지 미리 안다.
2. **필수 사실이 보인다.** 무게 제한, 길이, 고정 여부, 흐름 방향, 작동 주기를 필요 전에 확인한다. 화면과 텍스트의 사실이 일치한다.
3. **인과관계가 남는다.** 실패 기록에 적용된 문장, 행동 대상, 바뀐 상태, 막힌 이유를 표시한다.
4. **대안이 실제로 다르다.** 길을 바꾸기, 환경을 바꾸기, 도구를 쓰기 등 적어도 두 계열을 주요 퍼즐에서 허용한다. 안전한 첫 실습은 한 계열이어도 된다.
5. **뜻밖의 합리적인 풀이를 받는다.** 예문 밖 성공을 막는 별도 정답 문자열·해법 ID를 요구하지 않는다.
6. **새 개념 하나를 먼저 분리한다.** 처음부터 새 물건·새 시간 규칙·새 기억 규칙을 동시에 시험하지 않는다.
7. **모든 가설이 한 번은 해 볼 만하다.** 자원은 되감으면 복구된다. 보지 못한 정보 탓에 반복해서 죽이지 않는다.

실패 예시는 “틀린 행동이야” 대신 “네가 발판을 떠나자 문이 닫혔어. 문은 눌리는 동안만 열려”로 쓴다. 예상치 못한 동음이의어 해석을 웃음 소재로 삼아 플레이어를 죽이지 않는다. 웃음은 합의된 행동이 낳은 귀여운 물리 결과에서 나온다.

선택 힌트는 **볼 곳 → 관계 → 예시 문장**의 3단계다. 마지막 단계는 사용자가 명시적으로 더 요청했을 때만 보여 준다. 죽었다는 이유로 자동으로 답을 띄우지 않는다.

## 6. 화면과 서사

현재 [아트 디렉션](../art-direction.md)의 크림색 몸·민트 후드·금빛 달 장식을 기준으로 한다. 스토리 초안의 이전 외형 묘사를 새 에셋 기준으로 쓰지 않는다. 본문 호칭은 용사로 통일한다.

각 장은 배경 팔레트뿐 아니라 실루엣, 재질, 움직임, 물건의 결합 방식이 달라야 한다. 작동 가능 여부와 상태는 형태·위치·무늬·텍스트를 함께 써서 전달한다. 소리를 끄거나 모션을 줄여도 신호를 놓치지 않는다.

장당 선택적 복선은 한 장면/소품을 기본으로 한다. 필수 대사로 조작을 끊지 않는다. 보스의 기계 목표도 이야기와 무관하게 읽힌다. 마지막 편지와 불빛의 귀환은 클리어 이후의 짧고 건너뛸 수 있는 보상이다. 엔딩 전에 수신인이나 길잡이의 정체를 설명하지 않는다.

### 음악과 실제 장치 신호

장별 BGM은 분위기와 긴 호흡을 담당한다. 도입 스테이지마다 곡을 갈아 끼우지 않고 같은 모티프의 음색·층·여백을 바꾼다. 초반에는 실제 대상만큼 음악도 성기게 두며, 종합 구간의 고조를 템포 상승이나 입력 시간 압박으로 만들지 않는다. 장마다 같은 BPM을 강제하지 않는다.

사건 종료·잠금·종 신호·공격 전조는 실제 효과음과 시각 표시가 전달한다. 음악의 박자·선율·화음 변화는 정답 시점이나 아직 모르는 연결을 알려 주는 정보가 아니며, 음악을 끄거나 다른 마디에서 실행해도 같은 물리 결과와 같은 정보를 얻는다. 효과음도 끈 상태에는 기존 시각·텍스트 대체가 남는다.

작성·관찰·재시도는 긴 시간 반복되므로 멜로디 밀도와 소리의 층을 절제한다. 음악이 실제 장치 소리를 덮지 않아야 하고, 사망마다 인트로·실패 화음·절정 진입을 반복하지 않는다. 완료 뒤 보상 화음은 판정 후 연출이며 진행 조건이 아니다. 장별 제안은 음원 제작이나 오디오 동작의 구현 완료를 뜻하지 않는다.

## 7. 구현·플레이테스트 인수 기준

문서를 구현했다는 판정과 재미있다는 판정을 분리한다.

- 같은 상태에서 동의어·어순 변경·불필요한 수식어가 같은 의도를 유지하는지 확인한다.
- 대상, 순서, 기다림의 끝, 유지 주체를 바꾼 최소 쌍은 서로 다른 결과를 내는지 확인한다.
- AI가 아직 보지 못한 신호를 발명하거나 “알아서 해결”을 완전한 해법으로 확장하지 않는지 확인한다.
- 모든 주요 구간에서 문서의 대안 두 개를 실제 시뮬레이션으로 재현한다. 문장만 다르고 행동이 같다면 미충족이다.
- 상태를 초기화한 뒤 재시도, 다른 이전 경로에서 진입, 저장 후 재개에도 조건이 일치해야 한다.
- 장별 사람 관찰에서는 첫 이해까지 걸린 시간, 자발적 해법의 종류, 해석 수정과 추론 수정의 비율, 의도적 사망이 필요했던 횟수를 기록한다.
- 실패 원인을 설명하지 못하는 사람이 반복되면 설명문을 늘리기 전에 시각 신호·물성·배치를 고친다.
- 재시도 시간의 대부분이 이미 푼 길 재생이라면 압축을 강화하거나 체크포인트 범위를 재조정한다.

외부 게임 사례나 실제 플레이테스트 결과를 근거로 한 수치가 아니다. 출시 전 필요한 검증 항목과 설계 가설을 명확히 둔 것이다.
