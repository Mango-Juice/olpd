# 3장 — 태엽 부엌

> 현재 설계 v2 · 6장면 · 기준 화면 960×500. 코드와 검증 상태는 별도로 확인한다. 이전 복합 설계는 [역사 기록](../history/stage-design-v1/README.md)이며 구현 요구사항이 아니다.

## 장의 중심 — 보이는 사건을 기다린다

정밀한 시간 입력 없이 기계가 비워 주는 자리를 읽는다.

[공통 플레이 계약](00-play-contract.md)을 따른다. 현재 장면에서 무료로 문장을 고치고 다시 해 본다. 이미 마친 장면을 다시 통과할 필요는 없다. 이전 장의 설명서나 물체 속성표를 읽어야 풀리는 장면은 만들지 않는다.

## 사용자에게 보이는 문구

입장할 때 아래 목적 한 문장을 한 번 보여 주고 구분에 필요한 사물 이름만 남긴다. 확인 팝업은 없다. 명령 예시, 요소 역할, 세부 완료 판정과 해법은 개발자용 정보이며 UI에 표시하지 않는다. 해야 할 일은 알리되 해결 순서는 말하지 않는다.

| 장면 | 입장 목적 한 문장 |
| --- | --- |
| 3-1 숨 쉬는 배출구 | 편지와 함께 부엌 안으로 가야 해요. |
| 3-2 오븐의 박자 | 오븐 안의 빵을 꺼내야 해요. |
| 3-3 오르내리는 집게 | 집게 너머로 가야 해요. |
| 3-4 부푸는 디딤돌 | 위 선반에 올라가야 해요. |
| 3-5 다가오는 쟁반 | 건너편 식탁으로 가야 해요. |
| 3-6 김 사이의 배달 | 편지와 함께 부엌을 나가야 해요. |

## 제작·검증용 장면 명세

아래 수와 역할은 내부 설계 검증용이다. 도착점·위험·관찰 대상·조작 물건을 모두 세며, 일반 바닥과 배경 장식만 제외한다. 연결된 물건을 묶어 수를 숨기지 않는다. 용사와 등지기는 수에서 제외하지만 등지기의 별도 역할은 인지 부담으로 검토한다.

### 3-1. 숨 쉬는 배출구

- **요소 2개:** 김 분출구 — 주기 위험, 출구 — 목표.
- **공간:** 평평한 길의 중앙에서 김이 솟았다 멎는다. 카메라 이동이나 가로 스크롤 없이 출발과 결과가 함께 보인다.
- **단일 목표:** 김이 멎은 길을 지난다.
- **최소 의도 예시 — 사용자 비노출:** “김이 멎으면 건너.” 같은 의도를 다른 문장으로 써도 인정한다.
- **이번 장면의 한 초점:** 안전한 상태 기다리기. 익힌 동작은 새 설명 없이 재사용한다.
- **눈으로 보이는 인과:** 분출이 사라진 공간으로 용사가 움직인다.
- **회복:** 실패한 접촉이나 멈춘 이유를 짧게 보여 주고 현재 장면의 시작 배치에서 무료로 다시 한다. 해석이 불명확하면 실행 전에 무료로 확인한다.

### 3-2. 오븐의 박자

- **요소 2개:** 오븐 — 상태 변화, 빵 — 목표.
- **공간:** 오른쪽 오븐 안에 빵이 보이고 문은 열렸다 닫힌다. 카메라 이동이나 가로 스크롤 없이 출발과 결과가 함께 보인다.
- **단일 목표:** 열린 오븐에서 빵을 꺼낸다.
- **최소 의도 예시 — 사용자 비노출:** “오븐이 열리면 빵을 꺼내.” 같은 의도를 다른 문장으로 써도 인정한다.
- **이번 장면의 한 초점:** 사건 뒤 행동. 익힌 동작은 새 설명 없이 재사용한다.
- **눈으로 보이는 인과:** 오븐 문이 열린 다음 손이 안으로 들어간다.
- **회복:** 실패한 접촉이나 멈춘 이유를 짧게 보여 주고 현재 장면의 시작 배치에서 무료로 다시 한다. 해석이 불명확하면 실행 전에 무료로 확인한다.

### 3-3. 오르내리는 집게

- **요소 2개:** 집게 — 주기 위험, 출구 — 목표.
- **공간:** 중앙 집게가 위아래로 오가며 길을 가린다. 카메라 이동이나 가로 스크롤 없이 출발과 결과가 함께 보인다.
- **단일 목표:** 집게가 비킨 길을 지난다.
- **최소 의도 예시 — 사용자 비노출:** “집게가 올라가면 지나가.” 같은 의도를 다른 문장으로 써도 인정한다.
- **이번 장면의 한 초점:** 높이로 드러나는 빈자리. 익힌 동작은 새 설명 없이 재사용한다.
- **눈으로 보이는 인과:** 집게가 오른 자리와 용사의 이동 경로가 분리된다.
- **회복:** 실패한 접촉이나 멈춘 이유를 짧게 보여 주고 현재 장면의 시작 배치에서 무료로 다시 한다. 해석이 불명확하면 실행 전에 무료로 확인한다.

### 3-4. 부푸는 디딤돌

- **요소 2개:** 반죽 — 높이 변화, 선반 — 높은 목표.
- **공간:** 낮은 반죽이 중앙에 있고 오른쪽 위 선반으로 이어진다. 카메라 이동이나 가로 스크롤 없이 출발과 결과가 함께 보인다.
- **단일 목표:** 선반에 올라선다.
- **최소 의도 예시 — 사용자 비노출:** “반죽이 부풀면 밟고 올라가.” 같은 의도를 다른 문장으로 써도 인정한다.
- **이번 장면의 한 초점:** 기다림으로 생기는 길. 익힌 동작은 새 설명 없이 재사용한다.
- **눈으로 보이는 인과:** 반죽이 선반 아래까지 부풀고 발판이 된다.
- **회복:** 실패한 접촉이나 멈춘 이유를 짧게 보여 주고 현재 장면의 시작 배치에서 무료로 다시 한다. 해석이 불명확하면 실행 전에 무료로 확인한다.

### 3-5. 다가오는 쟁반

- **요소 3개:** 이동 쟁반 — 운반, 틈 — 위험, 출구 — 목표.
- **공간:** 쟁반이 중앙 틈 위를 양쪽 돌턱에 닿도록 왕복한다. 카메라 이동이나 가로 스크롤 없이 출발과 결과가 함께 보인다.
- **단일 목표:** 쟁반으로 틈을 건넌다.
- **최소 의도 예시 — 사용자 비노출:** “쟁반이 오면 타고 건너.” 같은 의도를 다른 문장으로 써도 인정한다.
- **이번 장면의 한 초점:** 가까워진 사건 기다리기. 익힌 동작은 새 설명 없이 재사용한다.
- **눈으로 보이는 인과:** 쟁반이 다가와 정차한 뒤 탑승하고 반대편에 내린다.
- **회복:** 실패한 접촉이나 멈춘 이유를 짧게 보여 주고 현재 장면의 시작 배치에서 무료로 다시 한다. 해석이 불명확하면 실행 전에 무료로 확인한다.

### 3-6. 김 사이의 배달

- **요소 3개:** 김 분출구 — 위험, 이동 쟁반 — 운반, 출구 — 목표.
- **공간:** 김이 쟁반 앞 길을 가리고 쟁반은 오른쪽 출구까지 이동한다. 카메라 이동이나 가로 스크롤 없이 출발과 결과가 함께 보인다.
- **단일 목표:** 김을 피해 쟁반으로 출구에 닿는다.
- **최소 의도 예시 — 사용자 비노출:** “김이 멎으면 쟁반을 타고 건너.” 같은 의도를 다른 문장으로 써도 인정한다.
- **이번 장면의 한 초점:** 익숙한 두 사건의 연결. 익힌 동작은 새 설명 없이 재사용한다.
- **눈으로 보이는 인과:** 김이 멎는 것과 탑승을 따로 보여 준다.
- **회복:** 실패한 접촉이나 멈춘 이유를 짧게 보여 주고 현재 장면의 시작 배치에서 무료로 다시 한다. 해석이 불명확하면 실행 전에 무료로 확인한다.

## 이야기와 장의 음악

식탁 아래 반으로 접힌 낡은 냅킨. “누군가는 내가 천천히 먹을 때까지 늘 기다려 줬다.”

이야기 소품은 장면 완료 뒤 짧은 선택 장면으로 보여 준다. 퍼즐 화면의 상호작용 대상이나 숨은 조건으로 추가하지 않는다. 모루와 편지, 등지기의 기존 서사 연결과 용사의 외형은 유지한다.

- **대표 분위기:** 늦은 밤 부엌의 조용한 장난기. 태엽은 바쁘게 움직여도 플레이어에게는 따뜻한 차를 기다릴 여유가 있다.
- **음색:** 짧고 둥근 목금, 낮은 클라리넷, 가벼운 피치카토. 음악 속 톱니 느낌은 드문 짧은 패턴으로만 주고, 실제 종·김 종료·집게 딸깍의 음색과 높이를 분명히 갈라 놓는다.

여섯 장면은 같은 장의 모티프를 이어 쓴다. 첫 장면은 성기게, 마지막에는 음색을 조금 모으되 실제 장치 소리와 구분한다. 실패 때 곡을 처음부터 재생하거나 음악으로 정답을 알려 주지 않는다. 음소거에서도 움직임과 인과를 모두 읽을 수 있다. 음악 제작 제안이며 새 음원 구현을 뜻하지 않는다.

## 이 장의 검증 경계

- 960×500 안에서 필수 요소와 출발·결과가 동시에 보이며 화면 밖 대상이나 가로 스크롤이 없다.
- 목적 한 문장 이외의 설명 없이도 무엇이 막혔고 행동 뒤 무엇이 바뀌었는지 몸·공간·움직임으로 읽힌다.
- 최초 장면은 한두 의도로 끝나고, 후반 재회도 긴 문장이나 물리 계산을 요구하지 않는다.
- 장면별 이름·요소 수·인과가 실제 렌더링과 일치한다. 장식으로 보이는 숨은 정답 물체가 없다.
- 실패 뒤 현재 장면만 다시 하며 문장 수정 비용과 앞 장면 재플레이가 없다.
- 플레이 시간과 재미는 사람 플레이로 검증하기 전까지 수치 성과로 주장하지 않는다.
