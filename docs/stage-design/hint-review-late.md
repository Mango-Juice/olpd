# 6~10장 첫 접촉 힌트 검토

대상은 현재 `src/campaign/spatial/middle.ts`·`late.ts`의 장면 30개다. 선택기는 현재 장의 여섯 장면 전체를 검색하며, 실제 실패 이벤트에서 관측된 근거만 후보로 삼는다. 문구는 충돌한 몸체의 `motion.contact.entity`, 천장 접촉의 `surface`, 또는 실제로 다가간 뒤 실패한 상호작용 기록에만 연결한다. 목적 문장이나 명령의 대상만으로 힌트를 고르지 않는다. 같은 물리 관계에는 같은 `key`를 사용해 반복 노출을 막는다. 아래의 **재사용**은 기존 문구 유지 또는 같은 key를 다른 장면에 연결한다는 뜻이다.

| 장면 | 판정 | 근거와 허용 트리거 |
| --- | --- | --- |
| 6-1 어둠에 가져가기 | 불필요 | `bodies: []`. 벽감의 조명 변화와 목적이 관계를 보여 준다. 목표 미완료만으로 등불 운반 힌트를 만들지 않는다. |
| 6-2 두 손으로 오르기 | 재사용 | 기존 `ladder-free-hands`. 사다리까지 실제로 접근한 `climb`가 손의 점유 때문에 실패하고 `motion.kind=interact`일 때만 허용한다. |
| 6-3 두고 가지 않기 | 불필요 | 등불과 함께 가라는 목적과 남은 등불 위치가 보인다. 출구 미완료는 접촉 기록이 아니다. |
| 6-4 빌리는 열쇠 | 추가 | 닫힌 `06-v2-4-door` 몸체와 실제 충돌할 때. 빈손 열기도 실제 접근 후 실패한 `interact` 기록이 있을 때 같은 문구를 사용한다. 네모난 자물쇠 홈만 관찰한다. |
| 6-5 같은 열쇠 | 재사용 | 아래·위 문 충돌에 같은 `square-key-door` 사용. 6-4에서 이미 본 홈을 다시 설명하지 않는다. |
| 6-6 불빛을 챙겨서 | 재사용 | 닫힌 `06-v2-6-door` 충돌에 같은 `square-key-door` 사용. 등불 운반과 열쇠 사용은 앞 장면에서 배웠다. |
| 7-1 첫 동행 | 재사용 | 기존 `keeper-rail`. 용사가 실제 `07-v2-1-rail`에 부딪혔을 때만 몸 크기 차이를 언급한다. |
| 7-2 잡고 있기 | 재사용 | 기존 `curtain-lifts`. 닫힌 `07-v2-2-curtain`의 봉에 실제로 막혔을 때. |
| 7-3 내가 지나간 뒤 | 재사용 | 같은 `curtain-lifts`. 너무 일찍 놓아 실제 `07-v2-3-curtain`에 닿은 경우만; 손을 잡고 있는 목표 상태만으로는 보여 주지 않는다. |
| 7-4 역할 바꾸기 | 재사용 | `07-v2-4-curtain` 충돌에 같은 `curtain-lifts` 문구와 key. 인물만 바뀐 막의 관계를 재설명하지 않는다. |
| 7-5 함께 나르기 | 추가 | 실제 접근 후 `needs-partner` issue가 기록된 상호작용 실패에만 “긴 의자는 양쪽을 함께 잡아야 들 수 있겠어.”를 보여 준다. 의자 접촉을 추정하지 않으며, 단순 낙하에는 이 힌트를 붙이지 않는다. |
| 7-6 둘이 도착하기 | 추가 | `07-v2-6-curtain`에 실제 접촉하면 새 관계인 `counterweight-hold` 안내 “줄 끝에 무게를 걸면 대신 잡아 줄 수 있을까?”를 보여 준다. 막을 올리는 일반 설명은 반복하지 않는다. |
| 8-1 안개 속 다리 | 재사용 | 기존 `fog-bridge-rail`. 난간 몸체 `bridge`와 실제 충돌했을 때 열린 쪽을 살핀다는 정도만 보인다. |
| 8-2 끊긴 쪽 보기 | 불필요 | 끊긴 왼쪽과 이어진 오른쪽이 화면의 주요 차이다. `bodies: []`이고 왼쪽의 추락은 `entity` 없는 `fall`이다. 목적 대상에서 경로 답을 추론하지 않는다. |
| 8-3 바람 깃발 | 재사용 | 기존 `fog-wind-lull`. 강풍 몸체 `wind`의 실제 접촉에만 붙인다. |
| 8-4 등불의 윤곽 | 불필요 | 6장에서 빛의 위치와 효과를 이미 배운다. 계단은 빛 조건으로 통행이 막히는 물체가 아니며, 이 장면만의 새 접촉 힌트는 추가하지 않는다. 이 장면의 낙하에도 새 힌트를 추가하지 않는다. |
| 8-5 문양이 닿는 곳 | 불필요 | 관측창의 두 다리 비교가 이 장면의 판단이고, 정답 경로를 문구로 알려 줄 이유가 없다. `bodies: []`; 잘못된 다리의 낙하에 `entity`가 없다. |
| 8-6 출발 신호 | 추가 | 실제 낙하가 기록된 뒤 장면 관측으로 “배에 올라타면 물길을 건널 수 있겠어.”를 보여 준다. 배와 부두의 접촉을 꾸며 내지 않으며, 승선 대상 상호작용 실패를 요구하지 않는다. |
| 9-1 기울어진 층계 | 조건부 관측 | 실제 낙하 뒤 계단이 불안정한 상태(`stairs.stable=false`)일 때만 “기울어진 계단 아래에 받쳐 줄 자리가 보이네.”를 보여 준다. 계단 접촉을 주장하지 않는다. |
| 9-2 종추의 틈 | 재사용 | 기존 `bell-swing`. `bell` 몸체와 실제 접촉했을 때 틈의 주기만 언급한다. |
| 9-3 이어진 풍로 | 재사용 | `lift`와 실제로 접촉했을 때 `tower-lift`를 보여 준다. 승강대 도달 실패나 무관한 바람판 조작만으로는 선택하지 않는다. |
| 9-4 어두운 층계 | 불필요 | 8-4의 등불·계단 관계를 반복한다. `bodies: []`의 대상 없는 낙하에 새 문구를 붙이지 않는다. |
| 9-5 서로 기다리는 층 | 조건부 관측 | 다리가 내려와 있지 않은 상태에서 실제 낙하가 기록되면 “다리가 내려와 있어야 발을 디딜 수 있겠어.”를 보여 준다. 접촉하지 않은 다리를 만났다고 표현하지 않는다. |
| 9-6 종 위의 문 | 재사용 | `bell` 충돌에 9-2와 같은 `bell-swing` 사용. 피난 홈은 이미 보이는 안전 자리라 별도 문구를 추가하지 않는다. |
| 10-1 팔이 비킨 자리 | 재사용 | 기존 `warden-arm`. `arm` 몸체와 실제 충돌했을 때만 궤도 변화를 언급한다. |
| 10-2 첫 갑옷 | 재사용 | 기존 `armor-plate`. 서 있는 `plate` 몸체와 접촉했을 때 경첩의 움직임을 암시한다. |
| 10-3 뜨거운 틈 | 재사용 | 기존 `armor-heat`. 뜨거운 `path` 몸체의 실제 열 접촉에만 붙인다. |
| 10-4 접힌 날개 | 추가 | 펼쳐진 `wing` 몸체에 실제 충돌한 경우에만 경첩을 관찰한다. 평범한 직진은 날개 전 낭떠러지에서 먼저 떨어질 수 있으므로 그 추락에 날개 문구를 붙이지 않는다. |
| 10-5 마지막 매듭 | 추가 | 실제 접근 상호작용이 `out-of-reach`로 기록될 때만 “걸쇠가 너무 높네. 아래로 내려오게 할 수 있을까?”를 보여 준다. 목표 미완료나 대상 없는 낙하만으로 걸쇠에 접근했다고 추정하지 않는다. |
| 10-6 돌아가는 문 | 추가 | 닫힌 `door`와 실제 접촉하면 “문 안쪽에서도 잡아 둘 수 있겠어.”라는 안팎 손잡이 관계만 알려 준다. 대상 없는 낙하에는 문 접촉 힌트를 붙이지 않는다. |

8~10장의 엔티티 ID는 `bell`, `wing`, `door`처럼 짧다. 문구 조회는 단일 ID가 아니라 `segmentId/entityId`로 해야 다른 장면의 같은 ID가 섞이지 않는다. 출구 미완료만으로 힌트를 만들지 않는다. 물체 ID 없는 낙하는 위 표에서 허용한 장면 관측에만 연결하며, 특정 물체에 접촉했다고 표현하지 않는다.
