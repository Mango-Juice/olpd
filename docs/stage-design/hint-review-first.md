# 프롤로그와 1장 발견 힌트 검토

범위는 건너뛸 수 있는 서사 프롤로그와 온보딩 4단계, 1장 8개 방(화면 1-1~1-12)이다. 프롤로그 대화 자체에는 물리 발견 힌트가 없다. 판정 기준은 `src/game/hints/chapter-one.ts`, `src/game/hints/discovery.ts`, `src/game/onboarding.ts`, `src/game/content.ts`의 현재 코드다. 도입 단계는 시도 중 안내 문구를 순서대로 보여 주며, 1장에서는 실제 사망 이벤트의 관측 종류에 맞는 아직 배우지 않은 발견 하나만 보여 준다.

| 장면 | 실제 근거 | 노출되는 안내와 경계 |
| --- | --- | --- |
| 1-1 한 걸음의 약속 | 도입 `first-step`, `clear` | 열린 문으로 움직이라는 단계별 온보딩 안내. 사망 뒤 새 물리 발견은 없음. |
| 1-2 끊긴 바닥 하나 | 도입 `single-gap`, `bridge` 또는 `pit` | 좁은 틈을 살피고 점프가 필요함을 안내. 완료한 단계는 `gap` 발견을 이미 배운 것으로 표시. |
| 1-3 머리 위 돌 | 도입 `low-arch`, `lowCeiling` | 몸 높이를 줄이는 안내. 완료 시 `low-clearance`를 이미 배운 것으로 표시. |
| 1-4 옆으로 난 길 | 도입 `side-path`, `pitCeilingPath` 또는 `spikesCeilingPath` | 정면 장애물과 연결된 샛길을 함께 살피도록 안내. 완료 시 `side-route`를 이미 배운 것으로 표시. |
| 1-5 첫 번째 기억 | `pit` 사망 | “이 정도 틈이면 뛰어넘을 수 있을 것 같아.” (`gap`). 도입에서 틈을 완료했다면 반복하지 않음. |
| 1-6 끊어진 약속 | `bridge` 사망 | 같은 `gap` 발견을 사용. 이미 도입 또는 이전 방에서 노출됐다면 생략. |
| 1-7 발밑의 반짝임 | `floorSpikes` 사망 | “가시 위쪽은 비어 있네. 바닥에 닿지 않게 건널 수 있을까?” (`floor-spikes`). |
| 1-8 고개를 낮추면 | `lowCeiling` 사망 | “몸을 낮추면 아래로 지나갈 수 있겠어.” (`low-clearance`). 도입에서 이미 배웠다면 생략. |
| 1-9 다른 길의 발견 | `pitCeilingPath` 사망 | “위아래가 막혔네. 옆길로 우회할 수 있겠어.” (`combined-hazards`). 이 관측은 단일 `side-route` 안내와 별도 발견이다. |
| 1-10 작은 지름길 | `spikesCeilingPath` 사망 | 같은 `combined-hazards` 발견을 재사용하며, 이미 1-9에서 노출됐다면 반복하지 않음. |
| 1-11 기억을 이어서 | 각 사망 이벤트의 `pit` 또는 `lowCeiling` 관측 | 후보는 각각 `gap`, `low-clearance`. 과거 노출 여부에 따라 아직 배우지 않은 가장 최근 발견 하나만 보여 줌. |
| 1-12 빛이 드는 곳 | 사망 이벤트의 `bridge`, `floorSpikes`, `lowCeiling`, `pitCeilingPath`, `spikesCeilingPath` 관측 | 각 기존 key를 재사용한다. 한 번의 사망 뒤 하나만 고르며 새 발견을 만들지 않는다. `clear`는 힌트 후보가 아니다. |

온보딩 안내는 세 문장으로 단계별 진행을 돕고, 실제 시도가 적용됐으나 성공하지 못한 경우에만 해당 단계의 발견 후보가 된다. 1장 힌트는 최종 이벤트가 현재 생의 마지막 사망인지 확인한 뒤, 저장된 이벤트에서 아직 배우지 않은 가장 최근 후보를 고른다. 온보딩 완료 기록은 같은 개념의 반복 노출을 막는다. 성공·막힘·진행 중 이벤트, `clear`, 단순 실패 이유 문자열은 새 힌트 근거가 아니다.
