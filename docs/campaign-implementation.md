# 10장 캠페인 구현 커버리지

> 현재 상태: **전체 장 구현 goal은 중단 유지. 사용자 후속 요청으로 2장 이후 해석 API에 DeepSeek V4.1 Flash를 적용하고 별도 검증했다.** 기본 non-thinking, 호출당 8초 제한이며 프롤로그·1장은 Jev를 유지한다. [통합 실측 보고서](campaign-deepseek-probe.md)를 참고한다. 이 전환은 7~10장 완료나 전체 goal 재개를 의미하지 않는다.

> 이전 중단 기록 (2026-09-22): 2장 필수 자유 한국어 입력을 현재 Jev 경로로 충족하지 못해 추가 구현을 중단한다. 전체 54구간 완료가 아니다. 아래 이전 작업 기록은 당시 상태이며, 현재 상태와 중단 근거는 이 절을 우선한다.

## 중단 근거와 보존 상태

- 확인된 컴파일러 결함을 교정한 `anchor → contextual verb → 역할 → joint 검증` 경로를 실제 Jev 1.13.0으로 평가했다. 최종 고정 코호트는 **8개 중 2개 성공**이다. 단일 탑승과 단일 하차는 성공했으나, 2장 도입의 두 연속 지시 및 물 붓기의 네 변형은 모두 실패했다.
- `세 칸 얕은 대야의 물 두 칸을 빈 통에 부어`에서 source는 대야, 수량은 2로 맞혔지만 destination도 대야로 선택했다. 관형절 유무, 두/세 칸, 숫자 2 표현을 바꾼 네 사례 모두 같은 방향 오류가 남았다. 무료 명료화로 거절하는 검사는 정상이며, 이를 통과시키려고 검사를 약화하지 않는다.
- 역할 정의의 잘못된 필드 참조, 행동 개수에 맞춘 낮은 확률 토큰 강제 추가, 동사 판정 단계의 현재 탑승 상태 누락을 교정했고 독립 코드 검토를 마쳤다. 교정 전·후 raw 요청/응답은 각각 `artifacts/campaign-jev-v4/cohort.json`, `artifacts/campaign-jev-v4-corrected/cohort.json`에 보존한다. 세부 판정은 [Jev 검증 기록](campaign-jev-probe.md)을 참고한다.
- 이는 Jev가 모든 문장에 쓸모없다는 보편적 주장이나 수학적 불가능 증명이 아니다. **현재 Jev 기반 구현으로 필수 2장 자유 입력 경험을 충족할 수 없다는 실용적 중단 판단**이다. 사용자의 조건에 따라 다른 provider, 키워드 파서, 정답 문장 강제, 고정 해법으로 대체하지 않고 goal을 중단한다.

| 영역 | 중단 시 상태 |
| --- | --- |
| 프롤로그·1장 | SKIP, 80자 제한, 비동기 캠페인 저장 연결 및 브라우저 검증 완료 |
| 캠페인 공통 | 지도·순차 잠금·저장/이전·재개·완료 archive·다중 탭·무료 명료화 구현 및 대상 검증 완료 |

| 7장 | 물리 5구간+연습 및 한국어 표시 코드 보존. 탑승/밧줄/암묵적 해제 회귀 보완. registry 미등록 |
| 8~10장 | 구현 미완료. 관측 참조·중첩 문법·보스·엔딩 등 남음 |

코드는 작업 트리에 보존했으며 배포하지 않았다. 자동 테스트의 typed/fixture 성공은 실제 Jev 자연어 성공을 대신하지 않는다.

## 완료 정의와 상태 표기

- **사용자 추가 중단 조건:** 장별 구현 중 Jev를 활용할 수 없는 실제 한계에 도달하면 해당 장 구현과 goal을 중단한다. 다른 모델·키워드 파서·고정 해법으로 몰래 대체하지 않는다. 한 번의 프롬프트 실패와 검증된 구현 한계를 구분하고, 중단 시 실패 문장·시도한 해석 구조·결과를 남긴다.

- `기존 기준선`: 현재 1장의 8개 방, 네 행동, 80자 입력, 메모·사망·지우개 규칙을 그대로 유지한다. 캠페인 회귀 검증은 아직 필요하다.
- `대기`: 설계만 있고 제품 코드·에셋·통합 검증이 끝나지 않았다.
- 구간 완료는 화면이 존재한다는 뜻이 아니다. **A/B의 물리 원인이 실제로 다르게 시뮬레이션되고, 자연어 표현이 같지 않아도 같은 의도면 통과하며, 저장·되감기·접근성 상태에서도 결과가 보존**되어야 한다.
- 안전한 첫 학습 구간과 기존 1장은 설계가 명시한 대로 단일 대표 계열을 허용한다. 억지로 두 번째 정답을 추가하지 않는다.
- 아래 모든 체크박스는 검증 증거가 생길 때만 닫는다. 문서 작성만으로 구현 완료 처리하지 않는다.

## 제품 범위와 출시 순서

1. **1장 기준선 고정:** 현재 튜토리얼과 8개 방을 회귀 fixture로 잠근다. 프롤로그 `SKIP`은 빈 메모장, 본편 첫 작성 기회 정확히 1회, 사망 0, 지우개 2개로 시작한다. 1장의 입력 상한은 Unicode 코드 포인트 80자이고 합성 행동이나 새 안전 정지를 소급하지 않는다.
2. **캠페인 셸:** 1장 클리어 뒤 장 선택 지도가 열리고, 프로덕션 해금 조건은 오직 바로 앞 장 `N-1`의 완료다. 미완료 장과 빈 장을 건너뛰어 진행 상태를 만들지 않는다. 같은 run을 재개하거나 되감을 때는 최초 발견 기회를 다시 지급하지 않는다. 완료 장에서 사용자가 명시적으로 **새 재도전**을 시작하면 그 run의 메모·자원·책갈피 원장은 새로 시작하고, 영구 완료·다음 장 해금은 보존한다.
3. **결정적 물리 코어:** 2장부터 대상, 위치, 부모 관계, 용량, 하중, 부력, 도달 거리, 장치 상태, 사건 주기와 실패 원인을 데이터로 실행한다. 판정은 고정 tick과 원자 행동 경계에만 의존하고 프레임률·배속·탭 정지·현실 시각에 의존하지 않는다.
4. **합성 자연어:** Jev는 정답 ID나 최종 성공 여부가 아니라 대상·주체·조건·순서·병렬·지속·종료·범위를 구조화한 프로그램을 반환한다. 게임 코어가 공개된 능력과 현재 세계 상태로 실행 가능성과 결과를 판정한다.
5. **코어와 UI의 순차 구현:** 각 장은 먼저 headless 세계·두 물리 계열·실패 로그·저장 재개를 통과시킨 다음 UI, Canvas, 사운드, 힌트, 접근성을 붙인다. 이는 개발 마일스톤 순서다. 출시된 장의 런타임 접근 조건을 추가하지 않으며, 플레이어는 바로 앞 장을 완료하면 다음 출시 장을 해금한다.
6. **통합 종합전:** 9장에서 앞 장 상태 조합을 검증한 뒤 10장의 세 봉인, 엔딩, 전체 캠페인 연혁을 연결한다.

## 구현 재개 로그

2026-09-22 작업 트리 기준이며, 파일 존재와 제품 통합 완료를 구분한다.

- **기초 진행 중:** `src/campaign/types.ts`, `catalog.ts`, `conditions.ts`, `notebook.ts`, `program.ts`, `scheduler.ts`, `validation.ts`에 직렬화 타입, 3값 조건, 작성 경제, 절차 커서, guard 스케줄링, 프로그램 경계 검증의 초안과 집중 테스트가 있다.
- **저장·진행 진행 중:** `progress.ts`, `run.ts`와 대응 테스트가 추가되고 있다. IndexedDB 마이그레이션, 다중 탭, 기존 localStorage 보존을 포함한 실제 앱 저장 경로는 통합 검증 전이므로 완료로 보지 않는다.
- **현재 1장 작업:** 프롤로그 SKIP의 코어/UI와 단위 테스트가 들어왔으나 브라우저 검증이 남아 있다. 1장의 나머지 기준선을 캠페인 타입으로 교체하지 않는다.
- **연결되지 않음:** 위 캠페인 모듈은 아직 `App`의 실제 진행, Canvas 장면, 프로덕션 `/api/interpret`, 장별 물리 콘텐츠와 연결되지 않았다. 따라서 2~10장 구간은 모두 `대기`다.

다음 구현 순서는 다음 세 갈래를 2장 수직 슬라이스에서 합치는 것이다.

1. **2장 수직 슬라이스:** 02-1 연습·본편, 02-2의 두 물리 계열, 발견 한 줄·실패 되감기·저장 재개를 headless 코어와 화면에서 끝까지 연결한다.
2. **프로덕션 합성 해석기:** 1장 API를 유지하면서 2장 요청에는 500자, 공개 entity 카탈로그, 버전 2 프로그램을 사용하고, Jev 출력 검증 실패·명료화·공급자 오류가 경제를 소모하지 않게 연결한다.
3. **캠페인 App 통합:** 1장 클리어 뒤 2장 해금, 장 지도, 연습/본편 분리, 새 노트 UI, 우선순위 커서 재생, IndexedDB 원자 저장과 기존 저장 마이그레이션을 실제 사용자 흐름으로 묶는다.

이 세 갈래가 G0~G4를 함께 통과하기 전에는 3장 구현이나 캠페인 배포를 시작한 것으로 표시하지 않는다.

## 공통 구현 계약

### 자연어와 실행 프로그램

- 1장은 기존 `action + appliesTo` 해석과 80자 상한을 유지한다.
- 2~10장은 앞뒤 공백을 제외한 Unicode 코드 포인트 1~500자를 클라이언트·API·저장 검증에서 동일하게 허용한다. 약 200자는 편하게 읽고 편집하기 위한 UI 권장치이며, 500자는 안전한 하드 상한이다. 조용히 자르지 않는다.
- Jev 출력은 버전이 있는 합성 프로그램이어야 한다. 최소 노드는 원자 행동, 순차, 병렬, 조건, 사건까지 대기, 상태까지 반복이고, 모든 대상·주체·속성은 현재 장의 공개 카탈로그 ID로 검증한다.
- 해석기는 별칭과 동의어를 대상 ID에 연결할 수 있지만 물체, 능력, 관측 사실을 생성할 수 없다. 모호함·없는 대상·불가능한 동시 역할은 실행 전 확인하며 작성 기회나 종을 쓰지 않는다.
- 성공 판정은 물리 상태의 목표 술어로만 한다. 샘플 문장 유사도, 숨은 정답 문자열, 해법 ID를 참조하지 않는다.
- 동의어·어순·불필요 수식어의 동치 집합, 대상·순서·종료·주체를 하나씩 바꾼 최소쌍, 프롬프트 조작·미관측 사실 발명 거부를 장별 Jev 평가에 포함한다.

### 결정적 세계와 우선순위 커서

- 모든 휴대 물체는 세계, 손, 고리, 탈것, 장치 홈 중 정확히 한 부모만 가진다. 복제·소실·숨은 소비를 허용하지 않는다.
- 사건 주기는 tick으로 저장한다. 일시정지와 탭 숨김은 tick을 진행하지 않고, 배속은 표현 시간만 바꾼다.
- 활성 메모는 화면 위쪽부터 평가한다. 선택한 지침에는 `program counter`와 현재 원자 행동을 저장해 조건이 사라져도 이미 시작한 절차를 처음부터 반복하지 않는다.
- 높은 우선순위의 명시적 guard만 다음 안전한 원자 경계에서 끼어든다. 중단 지점, 변경 상태, 재개 가능 여부를 기록하고 공중 순간이동이나 자동 성공을 만들지 않는다.
- 끝 조건 없는 `잡고 있어`는 유효한 무기한 유지다. 같은 주체의 이동 또는 후속 해제 지침이 시작될 때 끝난다. 시스템이 임의 종료 사건을 채우지 않는다.
- `unknown`은 `false`와 다르다. 미관측 조건의 부정으로 반대 사실을 얻지 못하며, 현재 시도의 관측만 기억 조건에 쓸 수 있다.

### 연습, 작성 경제와 되감기

- 2~9장은 장 시작과 각 5개 구간의 최초 안전 책갈피에서 발견 한 줄을 제공하되 장 시작과 첫 구간은 중복 지급하지 않는다. 10장은 여섯 비트와 봉인 전환의 중복을 같은 방식으로 막는다.
- 발견·실패·자진 되감기로 열린 작성 기회는 최대 1회이며 누적되지 않는다. 새 줄 또는 기존 줄 수정 중 하나에 쓴다.
- 장별 지우개 2개, 이후 수정·삭제당 종 3회 규칙을 원자적으로 기록한다. 명료화와 통신 실패는 비용이 아니다.
- 연습 공간의 메모, 실패, 물체, tick은 본편과 분리한다. 7장 무료 연습에는 유지와 함께 쐐기 고정·해제를 포함해 08-3의 선행 경험을 보장한다.
- 실패는 현재 장 입구로, 보스는 현재 봉인 시작으로 돌아간다. 메모와 책갈피 사용 이력은 남고 물체·장치·현재 시도 관측은 초기화한다. 같은 입력·같은 시작 상태의 이미 통과한 부분만 압축한다.

### 저장과 이전 버전 보존

- 진행 중 저장, 완료 장, 캠페인 해금, 책갈피 사용 이력, 활성 메모, 우선순위 커서, 세계 snapshot, 현재 시도 관측과 연혁을 버전 있는 IndexedDB 스키마로 통합한다.
- 한 상태 전이는 IndexedDB 단일 readwrite transaction에서 snapshot, 이벤트, 경제, revision을 함께 커밋한다. UI와 Canvas는 커밋된 결과만 재생한다.
- 기존 localStorage 1장 저장과 기존 IndexedDB 완료 기록은 읽기 전용 원본으로 먼저 검증한다. 새 DB에 변환본과 migration marker를 한 transaction으로 쓴 뒤 다시 읽어 동등성을 확인한 경우에만 새 저장을 활성화한다.
- 원본 localStorage, 기존 완료 기록, 손상된 payload와 recovery key는 자동 삭제·덮어쓰지 않는다. 마이그레이션 실패 시 1장 기존 로더로 복귀하고 내보내기·재시도를 제공한다.
- 여러 탭은 revision/lease 충돌 시 오래된 탭의 실행과 쓰기를 멈춘다. 저장 후 재개는 원자 행동 경계에서만 가능하며, 같은 snapshot으로 같은 다음 event가 나와야 한다.

### 공통 검증 게이트

- **G0 계약:** 장면의 목표, 필요한 물성, 도달 범위, 실패 원인, 단일 계열 예외가 데이터와 문서에서 일치한다.
- **G1 코어:** 대표 계열 A/B가 서로 다른 상태 변화로 통과하고, 합리적인 혼합·우회도 목표 술어를 만족하면 통과한다.
- **G2 해석:** 한국어 동치 표현과 최소쌍, 모호함, 미지원 능력, 미관측 사실을 실제 Jev로 검증한다.
- **G3 재현:** 되감기, 압축 재생, 저장 후 재개, 다른 이전 경로, 배속·일시정지에서 결과와 실패 이유가 같다.
- **G4 UI·접근성:** 키보드·터치·스크린리더에서 목표와 상태를 읽고, 색각 보정·음소거·모션 감소에서도 필수 신호가 남으며, 500자 편집과 모바일 키보드가 잘리지 않는다.
- **G5 사람 검증:** 첫 이해 시간, 자발적으로 발견한 물리 계열, 해석 수정과 추론 수정의 비율, 의도적 사망과 반복 이동을 기록한다. 문서의 목표 비율은 출시 성과가 아니라 조정 기준이다.

### 후속 참조 계약 결정

- 8장의 대상 선택은 실행 직전 해석할 참조와 이미 결정된 물리 행동을 분리한다. 장별 실행기는 계속 실제 개체 ID만 받게 하여 관측 선택 로직이 장마다 복제되지 않게 한다.
- 관측값은 현재 시도의 가장 최근 사실만 사용한다. 아직 모르는 값, 후보 없음, 후보 중복은 임의 대상이나 숨은 정답으로 대체하지 않는다. 명시적으로 이름을 지목한 대상은 관측 허가증 없이도 물리 실행할 수 있어야 한다.
- 참조 후보의 공개 정체성과 현재 보이는 물성, 기억한 과거 물성을 구별한다. 관측 이후 변한 세계를 해석 요청 시점의 정답으로 고정하지 않는다. 다중 조건·중첩 제어와 이 참조 계약은 현재 미구현이며, Jev 기본 의미 검증 결과를 확인한 뒤 해당 구현을 이어간다.
