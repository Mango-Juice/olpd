## 2026-09-23 — 영구 메모 수칙과 우선순위 교정 (로컬)

사용자 확인에 따라 메모를 일회성 작업 목록으로 취급하던 동작을 교정했다. [공통 메모 수칙](game-rules.md)이 현재 기준이다. 아래 과거 기록 중 “지시를 모두 마치면 정지”, 완료 표식에 따른 실행 제외, guard만 선점한다는 가정은 폐기한다.

- 매 판단 경계에서 화면 위에서부터 조건을 재평가해 첫 수칙을 선택한다. 실행 완료로 소모하지 않는다. 이동 도중의 다음 걸음에도 상위 수칙이 개입할 수 있다. 거짓인 바깥 조건은 아래 수칙으로 넘어가고, 확인할 수 없는 조건은 임의로 건너뛰지 않는다.
- 한 줄 내부의 명시적 순서·동시 행동·대기는 유지한다. 중단된 순서는 다시 선택됐을 때만 이어간다. 끝난 수칙이 계속 맞으면 다시 실행한다. 무조건 전진을 맨 위에 두면 아래 상자 조건을 가리는 것도 의도한 결과다.
- 이전 `completed` 표식은 후보 제외에 쓰지 않는다. 이 표식 때문에 메모 없음으로 멈춘 활성 실행은 맞는 수칙이 있으면 메모·데스·과거 기록을 유지한 채 재개한다. 물리적 충돌 정지는 자동으로 풀지 않는다.
- AI 프롬프트를 지속 수칙으로 맞췄고 버전을 `campaign-deepseek-20-persistent-rules`로 올렸다. 단순 조건문은 `if`, 명시한 기다림만 `wait`로 표현한다. 실행할 때 AI를 다시 호출하지 않는다. 사전 검사는 한 수칙의 전체 실행을 확인한 뒤 끝내며, 반복 때문에 512번 재검사하지 않는다.
- 전체 **70개 파일 822개 검사**, 타입 검사·빌드 통과. 현재 54개 공간 장면 풀이도 통과했다. 과거 fixture의 소모형 기대는 새 규칙으로 고쳤고, 명시적으로 여러 지역을 건너는 과거 복합 풀이의 적용 범위도 그 의도에 맞췄다.
- `npx tsx scripts/browser-persistent-rules.ts`: 전진 우선이면 상자 충돌, 상자 조건 우선이면 점프 후 천장 충돌, 성공한 밀기 수칙 재선택·새로고침, 예전 메모 소모 정지의 0데스 복구를 실제 브라우저에서 확인했다. API 호출 0회.
- `npm run test:browser`: 기존 도입 Enter·IME·취소·오류·재개·인계 및 후속 장 공용 메모장·부활·우선순위·지우개 흐름 통과. 응답 fixture 검사이며 실제 모델 자연어 정확도를 재측정한 것은 아니다.

## AI 입력 가드 및 기존 운영 검증

이번 작업에서 서버 해석 모델·임계값·API 본문 스키마는 바꾸지 않았다. 이전 실제 Jev 평가의 고정 합성 지침 85개 결과는 적용 조합 371/371, 전체 집합 53/53, 거부 입력 32/32, 튜토리얼·대표 문장 11/11이었다. 개발 중 보정한 평가 세트이며 전체 한국어 정확도나 독립 평가 성과가 아니다. 원본은 `docs/jev-evaluation-2026-09-21.md`에 있다.

이전 공개 HTTP 검증에서 연쇄 행동 문장, 무적, 데스 0 변경은 422 unsupported, 모호한 “그게 있으면 뛰어”는 422 uncertain이었다. 현재 메모의 정확한 조건 집합 충돌은 이 서버 가드 이후 `core.addInstruction`에서 별도로 검사한다. 기존 메모 원문을 서버에 보내지 않는다.

전진·점프·숙이기·우회는 아직 전역 공통 행동이다. 자유로운 발화 시점·강도·대상과 장별 행동 확장은 설계 제안이며 이번 코드 변경에 포함하지 않았다. 스토리는 `docs/story-concept.md`의 제안 문서만 작성했다.

기존 Vercel 프로젝트의 `/api/interpret` WAF는 IP별 30회/60초, 서버 인스턴스 제한도 병행한다. 이전 실제 GET 35회에서 31번째부터 429였다. 리전별 고정 윈도이며 전역 비용 상한은 아니다. 키는 서버 환경변수에만 두고 `AI_ENABLED=false`로 공급자 호출을 중단한다. 운영 로그는 모델·버전·토큰·지연·오류 코드만 남긴다. 이번 작업은 이 설정을 변경하지 않았다.
